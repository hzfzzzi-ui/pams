# 资料导入与事实写入

隔离候选中的账户、收支和同步来源读取以已发布且已确认的来源明细及其现金事实关联为依据；新库不要求创建 `pams_source_row`。新来源的创建时间使用来源明细实际创建时间；旧资料缺少原始导入或创建时间时保持未知，不用迁移时间冒充。隔离新库只读取统一来源，不使用旧来源行的兼容投影。未关联现金事实不计入该投影；草稿、跨账户或内容不一致的已关联事实显示为待核对，不作为已验证金额。旧库及历史资料未迁移。

## 三层架构：统一来源的隔离候选

隔离新库可通过 `scripts/bootstrap_isolated_sources.py --apply` 使用同一正式空库清单，在一个事务内初始化基础结构、来源及估值证据。该入口要求显式 `PAMS_SOURCE_BOOTSTRAP_DSN`、隔离开关、专用测试库名称与数据库标记，失败全部回滚；它不是存量库升级工具。隔离来源 HTTP 默认直接以来源批次、文件和明细保存草稿及核对，复用现有预检与事实规则，人工、CSV/Excel、OCR 和资金双腿不写旧导入批次或文件表。生产默认路径未切换。预检令牌使用显式测试专用密钥跨 worker 校验；密钥不进入数据库或日志，重放以发布时记录的令牌与事实关联为准。隔离环境仅使用统一来源写入，不使用旧导入表。

银行账单通过统一来源批次、原件和明细写入现金事实；跨账户转账只保存经人工核对的双侧来源确认及可追溯撤销。无法证明原件、账户或金额时确认失效，未核对的资料保持待核对。隔离环境未迁移旧数据，也不代表线上已切换。 匹配规则只生成待审核建议，不自动合并或去重；支付通道重复需明确核对同日、同币、同额的独立双方来源并人工确认，确认失效或撤销后恢复两侧。存在同额歧义时阻断确认；单侧或缺来源证据保持待核对。隔离新库支持与账户基币一致的外币银行流水，按业务日有来源的有效汇率生成 CNY 投影并保存核验证据；缺汇率时保留草稿、阻断发布。投影是市场参考汇率，不代表银行结算汇率；原件或汇率来源变化时证据失效。银行侧外币余额快照、单个银行账户的多币种余额和跨币种划转尚未支持；券商账户的逐币现金与完整范围按下文单独核验。

来源层由 `source_batches`、`source_files` 和 `source_items` 组成：批次按账户与业务类型组织，文件保存原件及哈希，明细保存原始字段、解析候选、位置和核对状态；`source_templates` 按账户和业务类型保存可复用的列映射。上传、API、人工是取得方式；CSV、Excel、PDF、图片是格式；模板、OCR、人工、API 是解析方式，不作为独立业务表。一个来源明细可产生多条事实，不能以来源明细 ID 全局唯一约束事实。

隔离库的 TradingView CSV 按账户保存原件和逐行来源；CLI 的 `stage` 暂存，`inspect` 查看明细并可指定 `--file-id` 查看原件，`review` 使用批次 revision 和备注逐行核对，最后 `publish --confirm` 发布。未核对行、原件/行内容或 revision 变化会阻断发布；六字段相同仅提示潜在冲突，不自动合并交易。持仓写入只接受与已确认原件及事实一致的输入，无法证明账户完整范围时标为部分，不能根据缺行推定清仓。该流程仅用于标记隔离库，不是存量库升级或线上操作。

`database/postgres/schema/074_unified_source.sql` 与 `domain/imports/unified_source.py` 定义来源层，已纳入空库清单，不能作为现有库升级脚本执行。隔离 API 使用来源直写，旧库、历史事实和线上运行未迁移。

候选约束批次账户、业务类型、文件哈希、同批次文件关联与批次内来源身份，并阻止原始文件及来源证据原位修改；解析候选和核对决定仍可编辑。隔离环境已验证来源和事实同事务关联、重放及冲突阻断。券商交易使用官方稳定编号核对跨报表重复，内容冲突阻断；相同事实可以复用，但当前不会将后续报表伪装为新事实的主来源或记录未实现的多来源贡献。其他跨批次来源不能仅凭同额或相似字段自动去重。历史事实迁移、存量库兼容和线上切换不属于本次隔离验证。

`075_source_fact_links.sql` 纳入空库清单，为收支、交易和持仓增加可空来源明细引用；旧来源身份和哈希仍保留，一条来源可关联多条事实及对方账户现金腿。持仓单列引用表示创建来源，当前值来源以不可变估值版本中的 `current_source` 为准；无法证明时返回未知。核对快照和关联约束不能替代账户事实预检或跨批次幂等，存量库升级仍需单独设计和授权。

同一持仓版本可以记录不同批次的明细及不同角色。例如同日更正保留 `holding_creation_source` 并记录经逐字段核验的 `current_source`；券商明确退出可以同时记录原合约身份核对和新报告零值来源。创建来源只说明原持仓如何建立，不代表参与了更正后的金额计算；这些记录也不证明输入集合完整或外部身份已认证。普通导入的当前来源和历史反查须重建已核准批次、文件和明细的完整快照，并核对发布结果与对应持仓；原件损坏或字段冲突时来源为未知，不能重放。跨报表重复出现的既有交易和现金事实目前仍只记录未关联观察，不能据此声称已建立该事实的多来源贡献关系。

IBKR 新库隔离同步以报表原文、明细和交易事实写入，持仓更新保存前后证据；无完整范围或明确零值时不能推定缺项已退出。独立现金事件同步与完整报表同步已在隔离库验证两种先后顺序、共用原件、重复运行、缺汇率待处理及补齐后重试。人工账户绑定和原文内容核验不证明券商或用户身份已认证。旧事实不会自动补关联，其他券商与历史事实未迁移；上述路径不能据此用于生产迁移或回填。

| 现有来源 | 隔离新库归属 | 必须保留的身份与信息 | 已验证能力及边界 |
| --- | --- | --- | --- |
| 银行账单 | 账户 + cash 批次、文件、明细 | 原批次、`source_uid`、账户、原币金额及币种、原始字段、人工对账关联 | 来源与现金事实原子发布；双侧确认与撤销另行人工核对并保持事务一致，歧义不自动关联 |
| IBKR 报表交易 | 账户 + trade 批次及明细 | `source_account_id`、`source_trade_key`、官方成交/交易编号、原币金额及原文 | 同报表重放和跨报表官方编号冲突已验证；后续来源对既有事实的多来源贡献仍未建立 |

本主题规定原件、暂存、预检、写事实和自动现金事件的边界。手工导入、既有同步、隔离修复各走自己的门禁；文档合并不启用任何发布开关。候选开发见 [GitHub PR](https://github.com/hzfzzzi-ui/pams/pulls)，运行能力核对对应发布评论及实际开关。

## 原件、账户与候选

账户绑定现有 account_code，来源名称如同花顺/金太阳不自动建立第二个证券账户。单批单账户，资料类型为交易/持仓/资金，允许多图、多文件；持仓批次可含现金余额成员以证明完整账户，但不能混成资金流水。

原件及来源行/图片位置、业务日期、hash、修订可追溯。填写/识别与核对/发布两步分开；同一记录编辑器服务手动补录和批次修改。保存/编辑只写暂存，不调用旧持仓/交易写接口。金额输入为字符串，显示保留原精度，计算与判断由后端完成。OCR 结果必须人工核对，不能当自动财务核准。

## 格式与访问

账户导入可通过显式运行库开关与数据库身份检查启用，访问范围限定账户导入请求；预检密钥与测试密钥分开，发布开关仍独立控制。配置和运行身份见 [配置来源](CONFIGURATION.md)，启用前应验证 schema、来源证据与并发写入路径。

以下为当前源码支持的格式；实际运行能力仍须核对部署版本与开关。

- CSV、TSV、XLSX、PNG、JPEG、账单 PDF 及同花顺原始文本型 XLS；二进制 XLS 和 WebP 不支持。
- 单文件 10MB，单批 30MB/10 文件/2000 候选；XLSX 限制解压总量、压缩比、工作表和单元格数，不执行公式、宏或外链。
- 图片受限为单帧、最多 20MP；本地 OCR 超时 20 秒，不调用云 OCR。引擎缺失、超时或列含糊时保留原件和警告，不制造数字。
- 新库使用 074 的来源批次、原件、明细和账户模板，不创建旧导入四表；存量库升级另行设计，原件以 BYTEA 私有保存。
- 导入共用 PAMS 的访问边界，不设置独立口令或解锁会话；仅在可信局域网或受保护网络使用。兼容字段 configured/authenticated 表示访问可用，不证明用户身份已核验。
- 所有修改要求同源 Origin，代理保留 Host 和正确 scheme。原件通过 API 提供，不暴露服务器路径或静态下载地址；响应不缓存，错误/日志不泄露凭据或连接串。
- capabilities 的 configured/authenticated 仅表示访问可用；authentication_required=false，schema_ready 与 publish_enabled 仍独立判断。

同花顺原始文本 XLS 必须具备成交日期、代码、名称、操作、数量、均价、成交金额和发生金额表头；保留原始字节、哈希、行号和原始列。拒绝二进制 XLS、冒名文件及公式。成交金额、净发生金额和余额分别表达；未知业务不猜测或丢行。

文件原始业务字段由服务端保持只读，允许排除、重复核准和对手关联等处理决策；截图与手工候选可编辑，但来源身份不可伪造。截图逐图确认绑定该图候选的字段与排除状态，修改后需重新确认。

手机流程先选择交易、持仓或账单类别和账户，再选择文件、截图或手工输入，三种来源共用核对与确认页。顶部返回或左边缘右滑只返回，不自动确认或写入；截图逐张查看原件和核对候选，文件记录通过映射重解析而不直接改写原始金额。确认本图只保存暂存核对状态，最终发布仍受整批预检和权限门禁约束。

预检的实际待写清单复用发布准备结果，列明目标表、操作、前后值和来源关联；预检 token 绑定该计划，生成的数据库 ID 只在事务成功后返回。账单使用既有收支事实和共享银行来源规则；余额独立确认，不因导入流水隐式更新余额。旧直接写入口返回 409，引导统一预检流程。

## 预检证据

来源日期、账户、币种、方向、标的和金额语义须明确。申请中基金保留草稿，未知金额/费用不补零。官方来源编号优先；同编号内容变化是冲突，无稳定编号的同日同量同价只是疑似重复，不能擅自合并真实多笔。

代码保留字符串和前导零；基金 A/C 按底表区分，未知/多义标的不自动新增。中文资产类型由单一适配器映射，保留原始类型；场所配置给出允许动作，券商 ETF 买卖与场外申赎分开，前端只绑定允许项。

成交额、净发生额、余额分别表达。手续费和税费分列时分别核实；明确合计时只记一次，不把未知税额拆分成零。金额/数量超出 schema 精度应阻断，不静默四舍五入。

预检绑定批次 revision 和账户事实指纹，有效 15 分钟；提交前重读。来源变化、过期、版本或并发冲突返回 409，不静默改变预期或自动重试写入。

## 持仓与资金完整性

持仓更新不制造买卖；交易流水不证明完整持仓与现金，导入不另建成本/收益算法。部分持仓只允许在已有同日完整集合内安全覆盖；新日期须覆盖既有成员，遗漏不能清仓，旧日期不覆盖较新状态。

成员证据取各标的/币种最后已知记录。明确数量、成本、市值都为零才能证明退出；不能用页面 50% 行数启发式、复制旧余额到新日或历史省略代替清仓证据。已核对未变成员计入覆盖，但不重复写入。人民币手工导入不发布外币或融资负债账户快照，不把借款或外币现金当人民币余额覆盖。隔离券商账户可单独核准账户映射、完整证券范围和逐币现金范围：原文、已确认证券身份及各币种现金与同日持仓一致，并按原文当日汇率核对完整净值分项及多空总额后，同事务发布账户范围证据；目前支持现金及明确记录为股票、期权、债券、基金或商品的持仓，逐类对照官方净值分项；其他分项必须具备明确多空双零证据，缺项、非零其他分项或已知旧成员未明确退出保持未知。账户映射和报表认证不因人工核对而成为已认证，折算还需独立汇率证据。 所有持仓增删改和账户范围发布共用账户事务锁；应用先取得账户锁再改行。外部客户端若先锁行可能触发死锁，数据库会回滚整个事务；调用方需重读并按账户先锁顺序重试，不能只重试事务中的某条语句。

余额记录与资金流水不同，申购不是外部入金。手工入出金要求显式人民币对方账户：同事务写投资事实及关联 cashflow_id 的反向银行现金腿。银行已有同日同额记录则阻断重复补腿；投资账户间划转的双账户证据不在该首期发布范围。

## 原子发布

PAMS_IMPORT_PUBLISH_ENABLED 默认 false，访问/预览可用不代表可写事实。开启须单独批准配置及部署。发布使用事务和账户锁，同批原子、重复幂等；来源、核对决定、事实及其关联在同一事务提交，失败全部回滚。技术运行事件使用结构化日志，已发布业务事实及人工确认由数据库保存。发布后批次只读，不提供一键回灌撤销。

导入不直接写 NAV、收益表、账户锚点或刷新物化状态。影响没有完整证据时明确不可预估；发布成功不等于资产或历史收益已核准。缺来源、历史不完整及未实现的登录抓取/邮件接入均不能标记完成。

## 事实来源与人工修正

任何获准修正都须保留 source_table、source_id、source_key、source_hash，幂等执行，保留业务备注和用户确认依据。现金流与投资事实关联必须写 cashflow_id；confirmed 匹配和备注不能被自动重算覆盖。此处要求不产生执行生产修账的授权，隔离修复见 [修复、发布与恢复](REPAIR_RELEASE_AND_RECOVERY.md)。

银行卡至券商在现金流事实中为 investment_funding，券商侧为现金 deposit，不改变证券数量或成本。中文备注通过 UTF-8 管道写入，获准执行时先设置：

```powershell
[Console]::InputEncoding = [System.Text.UTF8Encoding]::new($false)
[Console]::OutputEncoding = [System.Text.UTF8Encoding]::new($false)
$OutputEncoding = [System.Text.UTF8Encoding]::new($false)
$env:PGCLIENTENCODING='UTF8'
```

## 自动现金事件

这条链路与手工批次发布独立：只消费已发布日结中逐笔 CashTransaction，不从 CashReport 日汇总制造单笔。日结原文发布器保持 facts_written=0，事实由单独步骤处理。

PAMS_IBKR_CASH_EVENTS_AFTER 为空时保持既有同步行为；启用后只接收严格晚于该 ISO 截止日的现金事件及普通成交。scheduler 的 PAMS_IBKR_CASH_EVENTS_SYNC_ENABLED 默认 false；隔离新库使用 broker_processing_state 保存已发布原件关联的业务重试水位，技术尝试及错误仅写脱敏结构化日志。该链路尚未用于生产或存量库。GET /api/ibkr/cash-events/status 为服务器只读事务；POST /api/ibkr/cash-events/sync 最多 3 日/次，不接受请求改截止线、重标日期或绕过确认。

账户及父节账户别名、业务日、币种、稳定身份、显式有限金额/符号、完整 CashTransactions 节必须可证。缺节未知，显式空节可完成；未知类型/冲突隔离，已知事件继续处理，整批事务错误回滚。稳定源键去重，行 ID 变化不重写旧关联；原币金额或既存 CNY 投影冲突不得静默跳过或修正，比较遵循 NUMERIC 十位小数精度。

自动模式不执行旧跨来源 backfill，不用最新 FX 或缺失 1 制造新成交。缺同日汇率时保留可证原币成交、人民币换算保持未知；需要汇率才能发布的现金事件保留待处理并可在汇率补齐后重试。仅切开关不改变报告指纹、不重放旧持仓/历史/交易。券商侧本人入金可按证据确认，银行侧只关联唯一已证实身份；缺银行证据保留 bank_match_pending，不猜余额、不弹窗，也不能把券商侧已入账说成未入账。手工补银行腿与本自动规则不能互相代替。

现金事件处理不要求顺带执行 071 迁移，费用证据可保留 raw；不得对已含费用、利息、入金的现金或 NAV 再加减一次。截止线及之前历史不自动回填，银行链仍可能未闭合。

## 验证范围

解析/预览/草稿必须零业务事实写入；发布测试覆盖权限、幂等、来源/版本过期、并发、账户锁、失败回滚及审计一致性。隔离 PG16 使用显式 loopback 测试 DSN 和带标记可销毁库，不使用生产 PG* 注入故障。页面用隔离 API 验证写入，原页面可用固定 DTO 验证保留，生产财务对照独立执行。真实新资料带来的金额变化须可解释，不以金额永久不变作为导入验收目标。

## 账户期间资金流来源核对

普通账户期间资金流使用统一来源批次、原件和来源明细，不增加独立过程表。隔离环境中以 `POST /api/account-import/flow-coverage/stage` 提交 UTF-8 CSV，字段依次为 `account_code,period_start,period_end,event_date,side,currency,net_amount,external_id`。每行声明同一账户和完整期间；事件方向为 `deposit` 或 `withdraw`，金额带方向符号、标识对应已核验事实。无外部流时须用唯一 `side=none` 行明确声明空期间。

通过 `GET /api/account-import/flow-coverage/{batch_id}` 查看，再以 `POST /api/account-import/flow-coverage/{batch_id}/publish` 明确确认、填写备注与来源标识到事实 ID 的逐笔映射；系统验证版本、原件哈希、账户、范围、逐笔事实及来源。范围声明是人工核对，不代表系统认证了来源身份。多个连续批次可以共同覆盖期间；缺失、冲突、额外事实、非现金转移未核实或汇率缺失时不得推断收益。
