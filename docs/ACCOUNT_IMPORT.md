# 投资账户导入：范围、契约与验收

本功能为L级。生产暂存与预览已获准启用，发布仍关闭；运行事实以带时间的DEVELOPMENT_STATE及新鲜身份报告为准。
本轮同花顺原始格式适配仅提交候选PR，不合并、不部署、不生产写入或修账。main不追认为用户已验收stable，原工作区历史修改保留。

## 页面与来源

- 更多页保留原银行账单入口，新增投资账户导入子入口；底部仅投资/收支/更多。
- 账户先绑定现有account_code。同花顺/金太阳是来源入口，不自动建立第二个证券账户。
- 单批单账户，类型为交易/持仓/资金，支持多张图和多文件；持仓批次允许现金余额成员以证明完整账户，但不混入资金流水。
- 一套记录编辑器服务手动补录和批次内修改。候选修改只写暂存，不调用旧持仓/交易写入接口。
- 第一阶段填写/识别，第二阶段核对发布；原件、行号/图片位置、异常与来源日期可追溯。
- 原生表单输入金额为字符串；显示不改变原始精度；计算与数据判定由后端完成。

## 接入与隐私

- schema仅通过`database/postgres/schema/072_account_import.sql`进入单独迁移审批，无运行时DDL。
- 导入与其他PAMS页面共用应用访问边界，不再设置独立口令、解锁接口或会话Cookie；旧`PAMS_IMPORT_ACCESS_TOKEN`不再读取。能访问PAMS的用户也能查看导入原件和草稿，仅应部署在可信局域网或Tailscale内，不因此开放公网访问。
- 所有修改仍要求同源Origin；反向代理须保留Host和正确scheme。取消口令不取消来源校验、容量限制、预检、二次确认或独立发布开关。
- 原件以BYTEA保存在私有暂存表，仍经API返回，不暴露服务器文件路径或静态下载地址；响应不缓存。
- capabilities中的`configured`、`authenticated`保留为true兼容旧调用方，仅表达访问可用，不证明身份已核验；`authentication_required=false`明确无需独立认证，`schema_ready`与`publish_enabled`继续独立判定。
- 单文件10MB、单批30MB/10文件/2000候选；XLSX限制解压总量、压缩比、工作表/单元格数量。
- 不执行公式、宏或外部链接。PNG/JPEG只允许受限单帧图片，本地OCR有超时；不调用云OCR。
- 支持CSV、TSV、XLSX、PNG、JPEG，以及同花顺原始文本型XLS交易导出；账单另支持已配置来源的PDF解析，不把任意二进制XLS、HTML、PDF或WebP当成通用安全表格。OCR最多20MP/20秒、单帧，缺引擎/超时/不明确列保留原件及警告，不制造数字。

手机端三种输入、逐图确认、文件编辑边界、实际待写清单及旧入口收敛见[更多与导入整合](MORE_IMPORT_REDESIGN.md)。旧直接写入接口返回409和统一入口位置，不再兼容绕过核对的直接入库；既有投资/收支读接口和自动同步不受此入口变更影响。
- 暂存元数据及财务来源均有批次/原件hash/行号/修订；错误与日志不返回连接串或导入口令。

## 同花顺原生交易报表适配

- 原始`.xls`可直接上传，无须改名、另存或拆成多份。服务端只接收能按UTF-8/GB18030解码、具有明确成交日期/代码/名称/操作/数量/均价/成交金额/发生金额表头的文本导出；保留原始字节、hash、行号和全部原始列。OLE二进制、ZIP冒名、HTML、公式、超限或不明格式拒绝，不执行宏或外链。
- `account_import_ths`仅负责该来源的语义适配；现有预检、事实构造器、事务和发布门禁仍各自负责，不在前端新增金额或分类算法，不按某笔ID/日期/证券硬编码。
- 成交均价对应价格，成交金额对应交易总额，发生金额对应净收付。本次金额/余额是余额证据，不当作一笔交易金额；均价与成交额不闭合仍保留原校验，不改数字或放宽容差来凑一致。
- 证券买入/卖出、红利入账、红利税补扣、利息归本、银行转证券/证券转银行按明确业务词映射。未识别业务不丢行、不推断为买卖。利息/分红/税款与入出金不改变持仓数量和成本；原报表中的股息对应股数/余额继续保留在原文，不写成买卖数量。
- 缺少证券类型时，预览按既有资产底表/别名唯一匹配股票或基金，不按代码前缀猜测，不自动创建主数据。明确但不符的类型继续阻断，缺失/多义标的按证券代码汇总。详情仅绑定同批次/版本的服务端类型，不要求逐条选类型。
- 手续费与其他杂费用Decimal精确相加，作为非税费用；印花税单列。独立红利税补扣以该条原始净扣款识别税款，不再按买卖重复扣税。每个费用分项均须明确，缺列/缺值/非数/负数不补零，原始分项与合计来源可追溯。
- 统一优先使用定位串，缺失时用有效成交编号，并按账户、资料类型、业务日期、市场限定来源身份；全零/空编号不作为稳定身份。相同身份改内容仍为冲突；无稳定身份的经济重复继续待核对，不自动跳过或合并。
- 一个交易流水批次可预览证券事件和账户现金事件，无须用户拆文件。券商入出金不视为收入或投资收益；没有银行对手证据时统一保留待关联，不猜账户、不自动补银行腿。未来即使另行开启发布，仍须通过对手/已有资金腿检查，资金与交易关联在同一事务完成。
- 新来源的税款/利息/资金动作只由其服务器来源规则提供；普通手动录入、通用CSV及理财通动作集合保持，不把原生来源扩展外溢成新的默认交互。

本轮真实原文回放只在隔离库/固定只读投影进行，未重新上传或改动生产批次；生产旧草稿不自动重解析，需未来获准部署后显式重新预检。解析成功不代表所有历史资料已核准，也不代表允许发布。

## 发布原则

- `PAMS_IMPORT_PUBLISH_ENABLED`默认关闭，未来须单独批准配置及部署后才可开启。
- 明确来源日期、账户、币种、方向、标的及金额语义；未知不补零，申请中基金保留草稿。
- 手续费与税费分列时须分别核实；明确“税费合计”时仅按已知合计记一次，未知税额拆分留原始证据，不称税额为零。
- 官方来源编号优先；同编号改金额为冲突，同日同量同价但无稳定编号为疑似重复，不擅自合并真实多笔交易。
- 股票/基金代码保持字符串与前导零，基金A/C类按资产底表区分；未知/多义标的不自动新增主数据。
- 资产底表既有中文类型由单一导入适配器映射为表单类型，保留原始类型；交易方向由账户场所配置提供，券商ETF买卖与理财通场外申赎分开，前端只绑定允许项。
- 持仓更新不生成虚构买卖；交易事实不等于完整持仓和现金证明，不在导入功能新增第二套成本/收益算法。
- 持仓部分更新仅在现有同日完整集合内安全覆盖；新持仓日期须覆盖既有成员，遗漏不能清仓。旧日期不得覆盖更新状态。
- 成员证据取每个标的/币种最后已知记录，而非页面50%行数启发式；只有明确数量/成本/市值均零才证明已退出。历史省略但无清仓证据会阻塞完整快照，须补证，不能把旧金额复制成今日。已核对的未变成员计入覆盖、但不重复写入。
- 本轮不发布含外币/融资负债的账户快照，不把借款或外币现金当人民币余额覆盖。金额和数量超过既有schema精度时阻断，不静默四舍五入。
- 余额记录与资金流水不同；入金/出金须保留账户侧及银行侧关联，不能把申购再当外部入金。
- 每次预检绑定批次revision与相关账户事实指纹。提交前重新核对，过期返回409，不默默修改预期。
- 预检有效15分钟。发布使用可串行化事务及账户锁；来源变化、版本冲突和并发冲突返回409，界面不静默重试写入。
- 同批原子提交，重复发布幂等；失败事务回滚，发布审计与业务记录同事务。发布后批次只读，不能一键回灌数据库撤销。
- 入出金须显式选择人民币对方账户，同事务生成投资事实及关联cashflow_id的反向现金腿；若银行已有同日同额记录则阻断，不能重复补银行腿。投资账户间划转的双账户证据不在首期发布范围。
- NAV影响不具备完整证据时明确不可预估。导入不直接写NAV、收益表、账户级锚点或刷新物化状态；已有数据链路继续负责，不以“发布成功”冒称资产/历史收益已经核准。

## 验证与未覆盖

- 解析/预览/草稿不会改变业务事实；导入真实新资料后的金额变化必须可解释，不以金额永久不变为导入验收目标。
- PostgreSQL测试只使用显式loopback测试DSN、PG16和带标记的可销毁数据库；不使用生产连接环境注入故障。
- 新页面以隔离API测试写入、固定财务DTO测试旧页面；生产只读九关键接口/九核心表证明无主动写入。
- 本轮不补全历史收益、不实现登录抓取/邮件接入，不把缺源或不完整历史标记为已核准。
- 没有用户验收前不打stable。未部署代码、生产schema/开关尚未启用必须分别登记。
