# 投资账户导入：范围、契约与验收

本轮为L级新增功能。生产不迁移、不启用写入、不入账、不修账、不合并和部署。
发布基线为main，不追认为用户已验收stable。原工作区历史修改保留。

## 三个依赖PR

| PR | 输入与责任 | 输出 | 验收边界 |
| --- | --- | --- | --- |
| 1 暂存与结构化解析 | 同花顺/理财通CSV、TSV、XLSX、手动候选，按账户与资料类型解析 | 私有原件、来源行、可编辑草稿、账户模板 | 零业务表写入；格式/公式/容量/身份/版本冲突检查；发布不可用 |
| 2 识别与受控发布 | 本地图片识别、人工核对后的候选、当前账户事实 | 字段校验、重复/冲突清单、有限影响说明、显式批次发布和审计 | 默认关；只在隔离PG16测试事务、幂等、失败回滚与过期预检；OCR不是自动核准 |
| 3 两步页面与共用编辑器 | 新API的上下文、批次、原件、预检DTO | 上传/手动补录、资料填写/核对发布、详情编辑与批次历史 | 320/390/1280；只绑定API；保存草稿不发布，最终按钮才允许提交；旧页面保留 |

每个PR单独中文说明和最终head CI，后续PR基于前一开发分支，不靠提前合并完成依赖。
PR75保留部署记录随第一条相关PR归入；本轮不产生部署记录PR。

## 页面与来源

- 更多页保留原银行账单入口，新增投资账户导入子入口；底部仅投资/收支/更多。
- 账户先绑定现有account_code。同花顺/金太阳是来源入口，不自动建立第二个证券账户。
- 单批单账户，类型为交易/持仓/资金，支持多张图和多文件；持仓批次允许现金余额成员以证明完整账户，但不混入资金流水。
- 一套记录编辑器服务手动补录和批次内修改。候选修改只写暂存，不调用旧持仓/交易写入接口。
- 第一阶段填写/识别，第二阶段核对发布；原件、行号/图片位置、异常与来源日期可追溯。
- 原生表单输入金额为字符串；显示不改变原始精度；计算与数据判定由后端完成。

## 接入与隐私

- schema仅通过`database/postgres/schema/072_account_import.sql`进入单独迁移审批，无运行时DDL。
- `PAMS_IMPORT_ACCESS_TOKEN`至少24字符，建议使用密码管理器生成的高熵随机值；不是IBKR Token。
- 默认未配置即关闭。解锁发HttpOnly、SameSite=Strict、30分钟的签名会话Cookie，不在JS/URL保存口令。
- 所有修改要求同源Origin；反向代理须保留Host和正确scheme。通过HTTPS访问时Cookie带Secure。
- 原件以BYTEA保存在私有暂存表，只有已解锁会话能读取，不暴露服务器文件路径或静态下载地址。
- 单文件10MB、单批30MB/10文件/2000候选；XLSX限制解压总量、压缩比、工作表/单元格数量。
- 不执行公式、宏或外部链接。PNG/JPEG只允许受限单帧图片，本地OCR有超时；不调用云OCR。
- 本轮明确支持CSV、TSV、XLSX、PNG、JPEG，不支持旧XLS、PDF或WebP；OCR最多20MP/20秒、单帧，缺引擎/超时/不明确列保留原件及警告，不制造数字。
- 暂存元数据及财务来源均有批次/原件hash/行号/修订；错误与日志不返回连接串或导入口令。

## 发布原则

- `PAMS_IMPORT_PUBLISH_ENABLED`默认关闭，未来须单独批准配置及部署后才可开启。
- 明确来源日期、账户、币种、方向、标的及金额语义；未知不补零，申请中基金保留草稿。
- 手续费与税费分列时须分别核实；明确“税费合计”时仅按已知合计记一次，未知税额拆分留原始证据，不称税额为零。
- 官方来源编号优先；同编号改金额为冲突，同日同量同价但无稳定编号为疑似重复，不擅自合并真实多笔交易。
- 股票/基金代码保持字符串与前导零，基金A/C类按资产底表区分；未知/多义标的不自动新增主数据。
- 资产底表既有中文类型由单一导入适配器映射为表单类型，保留原始类型；交易方向由账户场所配置提供，券商ETF买卖与理财通场外申赎分开，前端只绑定允许项。
- 持仓更新不生成虚构买卖；交易事实不等于完整持仓和现金证明，不在导入功能新增第二套成本/收益算法。
- 持仓部分更新仅在现有同日完整集合内安全覆盖；新持仓日期须覆盖既有成员，遗漏不能清仓。旧日期不得覆盖更新状态。
- 成员证据取每个标的/币种最后已知记录，而非页面50%行数启发式；只有明确数量/成本/市值均零才证明已退出。历史省略但无清仓证据会阻塞完整快照，须补证，不能把旧金额复制成今日。已核对的未变成员计入覆盖、但不重复写入。
- 本轮不发布含外币/融资负债的账户快照，不把借款或外币现金当人民币余额覆盖。金额和数量超过既有schema精度时阻断，不静默四舍五入。
- 余额记录与资金流水不同；入金/出金须保留账户侧及银行侧关联，不能把申购再当外部入金。
- 每次预检绑定批次revision与相关账户事实指纹。提交前重新核对，过期返回409，不默默修改预期。
- 预检有效15分钟。发布使用可串行化事务及账户锁；来源变化、版本冲突和并发冲突返回409，界面不静默重试写入。
- 同批原子提交，重复发布幂等；失败事务回滚，发布审计与业务记录同事务。发布后批次只读，不能一键回灌数据库撤销。
- 入出金须显式选择人民币对方账户，同事务生成投资事实及关联cashflow_id的反向现金腿；若银行已有同日同额记录则阻断，不能重复补银行腿。投资账户间划转的双账户证据不在首期发布范围。
- NAV影响不具备完整证据时明确不可预估。导入不直接写NAV、收益表、账户级锚点或刷新物化状态；已有数据链路继续负责，不以“发布成功”冒称资产/历史收益已经核准。

## 验证与未覆盖

- 解析/预览/草稿不会改变业务事实；导入真实新资料后的金额变化必须可解释，不以金额永久不变为导入验收目标。
- PostgreSQL测试只使用显式loopback测试DSN、PG16和带标记的可销毁数据库；不使用生产连接环境注入故障。
- 新页面以隔离API测试写入、固定财务DTO测试旧页面；生产只读九关键接口/九核心表证明无主动写入。
- 本轮不补全历史收益、不实现登录抓取/邮件接入，不把缺源或不完整历史标记为已核准。
- 没有用户验收前不打stable。未部署代码、生产schema/开关尚未启用必须分别登记。
