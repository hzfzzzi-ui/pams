# 数据与收益口径

本主题规定事实来源、估值、收益、汇兑与分类的解释。规则适用于对应业务链路；能力启用按对应功能 PR 的发布记录及实际配置核对，验收以用户明确证据为准。

## 事实与展示

原始资料 → 业务事实 → 当前状态/资产主数据/统一引擎 → API → 前端。页面、临时 YAML 和旧分类接口不得成为新的事实来源。

| 对象 | 职责 |
| --- | --- |
| pams_cashflow_fact | 收支、内部划转、投资资金进出及现金收益 |
| pams_investment_trade_fact | 买卖、分红、费用、换汇和投资账户资金事件 |
| pams_holdings_snapshot | 当前持仓快照，与交易事实配合使用 |
| pams_asset_master / alias / industry_map / theme_map / fund_underlying_position | 标的身份、分类及基金底层 |
| pams_portfolio_valuation_state | 发布组合资产、负债、净清算价值及其日期/质量 |
| exposure_engine / lookthrough_state / return_attribution / risk_state | 分析与风控的统一结果 |

收支页消费现金流事实，交易页消费交易事实，持仓页消费快照及交易事实。前端不新增分类、收益、NAV、风险公式或补差逻辑。未知金额、费用、汇率、日期或来源不补零。写入与来源关联规则见 [资料导入与事实写入](IMPORT_AND_FACTS.md)。

## 估值、收益和归属

组合净清算价值 = 总资产 − 总负债。assets_cny 包含持仓及各账户现金；liabilities_cny 包含融资、保证金负债等；net_liquidation_value_cny、as_of、status、quality_flags 同时表达值、日期、完整性与缺口。

持仓页顶层、收益/NAV 曲线终点、风险分母和配置占比应消费同一有效估值证明。历史发布值不得仅凭相同 XML 覆盖当前结果，还需匹配实际 FX、归属比例和账户输入。持仓账面盈亏、区间收益、NAV 与归因分别追溯；杠杆持仓 gross 市值不是账户净资产，负债不并入现金缓冲，投资入金不当收益。

IBKR 日结、估值与收益保留以下边界：

- 官方 NAV = 现金 + 证券 + 应计利息 + 应计股息 + 明确列出的其他 NAV 成分；Long/Short、分项及子成分交叉核对，不重复相加，已结算进现金的利息不再扣一次。
- 期间盈亏 = 期末 NAV − 独立期初 NAV − 期间净外部流量。证据应为完全同范围桥接，或连续且端点一致的逐日 ChangeInNAV；缺期初、缺日、未知字段均不补零，YTD 入金不能替代任意期间流量。
- 旧 return_ratio 是简单资本回报比：期间盈亏 /（期初 NAV + 期间净外部流量），不是 TWR、MWR 或个股持仓收益率。资本基数不为正时无定义，前端显示 --，不能制造 0%。后端显式提供 return_capital_base/cny。
- 新日结证明及展示 FX 均可用时，前端直接绑定 NAV、期间盈亏和资本基数；不能用“证券＋现金”或“NAV－入金”覆盖。未启用时保持原兼容路径，缺字段不得将新口径零值化。
- 官方账户基币按同业务日内部 FX 折算展示币，缺 FX 不默认为 1，也不取未来值。期末外币盈亏乘期末 FX 是展示折算，不等于人民币期间投资收益；原币逐项估值与基币再折算的差异独立桥接。
- gross assets/liabilities 须有官方总 Long/Short 证据，不能按净 NAV 正负伪造。完整 performance 保持完整账户语义；portfolio_account 是独立的组合身份/归属 join，身份、FX、归属均有证明才启用，比例只应用一次，零归属不显示虚构收益率。
- 账户总览保留平台原始值，primary 余额绑定共享确认值和历史 FX；输入证据变化使旧审批失效。沿用上一有效历史值时返回原日、请求日、过期状态，不能假称当日确认。持仓盈亏投影与 NAV 投影分别处理。

## 每日收益窗口

组合估值历史行的 `valuation_meta` 附带来源表、业务日期、发布状态、完整度、周期和状态哈希等字段。此处 `source_hash` 是现有组合估值状态的哈希，不能证明每个输入的身份。旧 NAV 回退缺少可证明的发布与质量信息时标为未知。`daily_accurate_eligible` 为三态：草稿及失败值为 `false`；已发布或缺少证据时为 `null`，不将发布、完整度或单一账户日结推定为全组合准确日结。周期类型证据不足时为 `unknown`；这些字段不改变原金额和历史行选择规则。

持仓与估值的多来源贡献关系是后续数据契约，当前接口尚不能证明完整链路，`input_lineage_status` 固定为 `unknown`：

- 计算结果须有独立、不可变的结果版本身份，记录结果范围、账户/资产、业务日期、本位币、计算版本及生成时间；修订应形成新版本，不能把可覆盖的持仓行 ID 当成不可变版本。
- 每个结果版本可关联多个贡献输入，同一输入也可关联多个结果。每条关联应记录角色（持仓事实、交易、行情、汇率等）、输入的稳定身份及版本或内容哈希、原始来源、输入业务日/观测时点、质量及引用方式；不同时间或来源的行情、汇率不得合并成单一伪来源。
- 历史持仓快照具备 ID、账户、资产和 `as_of`，但按账户、名称、日期更新，不能单凭 ID 证明历史版本。行情快照具备日期、价格时点、来源、状态和可选哈希；汇率具备日期、币种对、来源及获取时点，但两者现有记录均可能更新，不能只凭当前值补造过去版本。
- 关联必须由实际计算输入产生并可核验；缺少输入身份、版本、时点或质量时单项保留未知，不能由结果日期、单条来源或一次发布推定全部输入准确。没有关联记录与已确认没有输入是不同状态，旧数据不自动补造贡献记录。

亚太收盘后更新亚太收盘价、基金/港股预估及美股预估；美股收盘后确认相关美股、港股、QDII 和场外基金收益。北京时间 07:00 后前日收益进入历史，今日窗口滚动。具体市场及基金状态依赖实际来源日期，不由页面时钟制造确认。

银行卡转账、券商到账及投资资金进出不得进入投资收益。调度日期、高水位、重试和官方日结发布规则见 [券商同步与对账](BROKER_SYNC_AND_RECONCILIATION.md)。

## 每日汇兑归因

return_attribution.daily_fx_attribution 是只读解释，不是 NAV、账目、累计盈亏或收益率的新来源。证券汇兑估算与账户净汇兑分开：证券可随上市地日期更新，账户桥接必须使用同一已发布日结的相邻有效账户日；输出请求日、核对日和期初日，不能把不同日期确认值合为今日收益。

| 模块 | 责任 |
| --- | --- |
| ibkr_daily_close_read.load_evidence | 校验清单和原文字节哈希，不下载、刷新或入账 |
| ibkr_daily_fx | 复用日结账户/日期/NAV门禁，读取原币证券、正负现金、现金分类、ConversionRate及严格历史FX |
| daily_fx_bridge | 纯 Decimal 计算，不访问文件、网络、数据库或 endpoint |
| return_attribution | 只附加解释字段，保留原金额及原维度 |
| 前端 | 绑定解释及状态，不重算汇率、收益、融资或差额 |

R 为每单位原币折人民币的日终汇率，P 为证券市值，C 为有符号现金，T 为交易现金本金（卖出正、买入负，不含费用），I 为现金收益，E 为有符号费用，F 为净外部资金流入。

```text
价格收益 = (P1 - P0 + T) × R1
证券汇兑 = P0 × (R1 - R0)
现金汇兑 = C0 × (R1 - R0)
净汇兑 = 证券汇兑 + 现金汇兑
收益/费用 = I × R1 / E × R1
未解释原币现金 = C1 - C0 - T - I - E - F
资产现金期间盈亏 = (P1+C1)×R1 - (P0+C0)×R0 - F×R1
```

这是日终平移约定，不是逐笔成交时点的已实现换汇收益。融资负现金自然抵消证券敞口，不再额外扣融资本金。换汇、衍生品、未知现金分类及官方 NAV 的应计/其他成分保留独立差额；未证明原币归属的应计不能归入净汇兑。

CNY 自身汇率严格为 1；人民币基金净值已含底层 FX 时不再叠加。工具计价币不等于经济敞口币。原币至报表本位币使用同日官方 ConversionRate，再乘同日内部本位币至 CNY 汇率，保留日期/来源/组合方式。内部历史 FX 恰好同日，不取未来、最新或上一日替代。缺身份、现金、日期、分类或 FX 返回 null 和覆盖原因；舍入差、未知活动及原币现金残差保留，状态容差不修改金额或吞掉未知活动。

## 交易展示

字段统一为日期、标的名称、平台/账户、中文方向、金额、份数、税费、币种。deposit/cash_deposit 显示“入金”；withdraw/withdrawal/cash_withdrawal 显示“出金”；transfer_in/out 显示“转入/转出”。买卖标签不附加 auto。

## 分类与穿透

`lookthrough.yaml` 的 `aliases` 表示同一资产的身份别名，可同步到资产主数据；`lookthrough_aliases` 仅用于沿用穿透分类映射，不能作为资产身份别名同步。联接基金与被跟踪 ETF 是不同资产，此配置变更不会自动修正已存在的主数据记录。 对历史上明确误关联到 `ETF_QQQ` 的四条联接基金身份别名，身份匹配会跳过这四项；数据库原记录保持不变，直接写入的资产 ID 和其他未知错误仍需单独核实。

行业、主题、资产类型、市场、地区、币种及底层暴露分别表达。

行业白名单：金融地产、大消费、科技TMT、高端制造、周期资源、医药医疗、稳定公用、未穿透 / 未映射。

现金、债券/货币基金、ETF/基金、非上市股权属于资产类型；指数成分属于指数成员；AI/算力、半导体、互联网平台、贵金属与铜属于主题；人民币/美元、中国/美国属于币种或地区。这些均不能混入行业图。

主题为可重叠多标签，不要求加总 100%，主图不使用 donut。AI/算力子主题在点击详情展开，父主题去重。同一标的可以在配置中属于股票，在风险中同时具有资源、黄金、铜等暴露。

## 验证与保留范围

固定输入验证净值/收益分离、归属一次、同日 FX、CNY 恒零汇兑、融资抵消、平汇率、交易本金转移、收益/费用/资金分列、应计单列、残差、精度、错误账户、缺失/过期/未来/冲突来源；需要数据库时使用隔离 PostgreSQL。正式发布的九接口/九表对照、页面验证和用户验收按工作流程独立执行。文档合并不新增 schema、回填、修账或界面变化。
