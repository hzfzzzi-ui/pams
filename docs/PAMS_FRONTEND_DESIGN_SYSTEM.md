# PAMS 前端设计系统收敛 v4

本文件定义 PAMS 前端后续改动的视觉边界。目标不是重做 UI，而是把既有的移动端 dark app 风格（保留边界不代表已验收稳定版）收敛成可维护的组件契约，减少同一类卡片、标签、列表在不同页面重复实现。

页面/交互保留清单、代码分工、现有 API 消费面及待确认字段统一见 [页面与接口边界](PAMS_PAGE_BOUNDARY.md#前端整改与并行后端重构的边界)。后端“主表、来源表、辅助表”重构与前端整改并行；本文件只约束展示和交互，不建立新的财务口径。

## 设计定位

PAMS 是个人资产控制台，不是营销页。界面应优先服务三件事：

1. 快速判断资产状态。
2. 明确数据口径和更新时间。
3. 支持进一步下钻，而不是在首屏堆满解释文字。

视觉关键词：

- 克制、紧凑、高信息密度。
- 深色金融终端底色。
- 绿色 / 红色只表达收益与风险，不做装饰。
- 蓝色只表达导航、数据状态和可交互入口。
- 大卡片只用于核心状态区；普通列表、设置入口和检查项使用紧凑行。

## 样式分层

当前前端样式分三层：

```text
style.css
  旧全局样式、页面历史样式、现有业务模块样式

design-system.css
  新增设计系统覆盖层，只放 token、app-shell、共享组件和密度规则

页面内 style
  仅保留页面特有布局，后续逐步迁移到共享组件
```

`design-system.css` 必须在带版本号的 `style.css?v=...` 后加载。它不承载业务布局，不写接口相关样式，不直接绑定投资收益、风险、收支等业务含义。

正式页面的 `<body>` 必须带 `app-shell` 类。`ui.js` 仍会补充导航增强和预加载，但设计系统基础样式不能依赖 JS 执行后才生效。

## 页面骨架

正式页面只保留三类主入口：

- `investments.html`：投资。
- `ledger.html`：收支。
- `more.html`：更多。

低频页面从“更多”进入：

- `accounts.html`
- `data_sources.html`

页面结构应保持一致：

```text
底部主导航
  -> 页面内二级导航 / tab
  -> 核心状态区
  -> 主列表 / 图表 / 检查项
  -> 点击后底部浮层或详情
```

不要恢复大 hero、状态栏大按钮、同步大入口条或旧独立风险页。低频工作台页面如果需要页面说明和快捷入口，使用 `.appWorkHeader`；不要恢复或新增 `appPageHero` / `appHero*`。

## 组件契约

后续新增 UI 时优先复用这些现有类或它们的语义：

- 面板：`.card`、`.investmentPanel`、`.portfolioRiskCategory`、`.portfolioRuleNode`
- 列表行：`.ledgerListRow`、`.syncCenterRow`、`.moreRow`
- 状态标签：`.statusBadge`、`.tag`、`.statusChip`、`.flowTag`
- 操作按钮：`.btn`、`.ledgerActionBtn`、`.reviewBtn`
- 工作台头部：`.appWorkHeader`、`.appShortcutGrid`、`.appShortcutCard`
- 底部浮层：`openBottomSheet`

新增页面如果需要新的卡片或列表，应先判断是否能复用上述结构。不能为了单页视觉效果新增一套完整组件。

## 移动端密度

移动端优先规则：

- 一屏先展示状态，不展示说明书。
- 列表行保持可扫读，标题、金额、状态三要素优先。
- 长解释进入详情或折叠区域。
- 热力图单元格优先展示标的名称和核心金额，完整解释放点击浮层。
- 交易、风险、配置页允许高密度，但必须有清晰点击入口。

## 回归要求

涉及前端设计系统的改动至少运行：

```powershell
python -m pytest tests/frontend/test_frontend_static_contract.py -q
```

仅在获准部署受影响 web 且没有可复用的已验证候选时，才执行相应构建/切换。以下为示例，不是文档修改的必跑项：

```powershell
docker compose up -d --build pams-web
```

如果新增正式页面，必须接入：

```html
<link rel="stylesheet" href="assets/css/style.css?v=20260620-mobile-density-v1" />
<link rel="stylesheet" href="assets/css/design-system.css?v=20260620-visual-cohesion-v1" />
```

并补充静态契约测试，防止页面绕开设计系统。


## 前端保留与最小改动规则

### 前端保留边界（不代表版本已验收）

投资页、收支页、更多页、风控页已经是移动端 dark app 风格。不要因为数据问题重做 UI。

硬规则：

- 底部移动端 nav 只能有：`投资`、`收支`、`更多`。
- 不要恢复旧的顶部 `statusbar` 到收支页和风控页。
- 不要恢复旧的多按钮入口条，例如同步、口径、风控一排大按钮。
- 交易页手动录入和筛选是折叠按钮入口，不要恢复成常驻大表单。
- 交易明细默认显示前 10 单，通过“展开更多”显示全部，不要显示“最近10单”冗余标签。
- 前端组件只展示 API 结果，不能在多个 JS 组件里重复实现行业、主题、地区、币种、资产类型分类。

相关回归测试优先看：

- `tests/frontend/test_frontend_static_contract.py`
- `frontend/public/investments.html`
- `frontend/public/assets/js/transactions.js`
- `frontend/public/assets/js/ui.js`
- `frontend/public/assets/css/style.css`

### 前端改动最小化

除非用户明确要求 UI 改造，否则：

- 不新增大段 CSS。
- 不改颜色、圆角、阴影、页面密度。
- 不重排页面主结构。
- 只做字段绑定、文案修正、数据质量提示、缺失列表或必要交互修复。

若确实需要改 HTML/JS：

1. 先确认当前页面已有结构。
2. 只改对应模块。
3. 加静态契约测试。
4. bump JS/CSS 版本号。
5. 验证候选构建；生产 `pams-web` 的重建/切换须另获部署授权。
6. 按 [工作流程第 0.2 节](DEVELOPMENT_WORKFLOW.md#02-测试验证分层抽样与证据复用) 选择页面范围，在候选环境及获准部署后进行对应可见验证。

## 构建生成的手机样式

投资页和更多页使用构建生成的 style-phone.css、design-system-phone.css；源文件与转换工具位于 frontend/public/assets/css/ 和 frontend/tools/mobile_styles.py。文档中的基础样式示例不要求把当前页面改回旧引用。页面职责以 [页面边界](PAMS_PAGE_BOUNDARY.md) 为准；实际样式使用须核对 HTML、Dockerfile 和生成工具。

更多页沿用投资页的字体、背景、主文本和手机留白变量；使用紧凑列表，高级工具默认折叠，待处理入口按数据状态显示。更多页局部样式放在 more.css，限制于页面作用域，不在导航组件计算财务数据。验证应覆盖手机和宽屏、正常与异常状态、折叠交互、键盘焦点和横向溢出。


## 更多页的视觉与验证细节

更多页继承投资页的 `pams-font-sans`、背景和文本变量，不另加字体、CDN 或独立主题。一级菜单沿用持仓名称的 16px、900 字重和 1.28 行高；标题使用 18px，二级工具使用 14px，辅助信息和分组标题保持较弱层级。使用平铺列表和细分隔线，不把资产数值大字号、等宽数字或收益红绿移植到普通菜单。

手机内容宽度及水平留白与投资页一致；高级工具默认折叠，展开只改变相关控件状态，不改变其他菜单的文本色。更多页局部样式限制在 `body.page-more`，不借局部修正改动全局折叠、投资或收支页面样式。

涉及该页面布局或共享样式时，按工作流程选择手机及宽屏覆盖；需要完整布局验证时覆盖 320、390 和 1280 视口、长标题、正常与异常状态、展开/收起、键盘 Tab/Shift+Tab 焦点与横向溢出。固定 DTO、禁网替身或模拟浏览器结果只证明对应候选，不代替真实设备、运行版本及财务核验。

## 组件整理边界

当前为原生 HTML、CSS、ES Modules 多页面结构，共享组件主要通过类名、HTML 模板和 `ui.js` 函数复用。下表是渐进整理的责任划分，不表示已经建立新的组件库。

| 组件族 | 当前实现 | 需要固定的契约 |
| --- | --- | --- |
| 主导航与页面外壳 | 各页 `.nav`、`ui.setActiveNav`、移动端增强 | 仅投资/收支/更多；子页归属和深链不丢失，保留 dark app 风格 |
| 二级 tab 与折叠 | 投资/收支/账户各自状态、`details` | 当前项、键盘操作、返回路径、按需加载；不让视觉抽取重置用户选择 |
| 资产/账户/流水列表 | 各业务模块及 `.ledgerListRow` 等 | 名称、金额、币种、日期、状态；长名称、大金额、空值、负现金、多账户下钻 |
| 详情弹层 | `ui.openBottomSheet` 与业务模板 | 标题、关闭/返回、滚动、遮罩、Escape；抽取时核对焦点进入与恢复，未测不能称可访问性通过 |
| 状态与标签 | `dataStateHtml`、`renderDataState`、各类 badge | 加载、空、错误、预估、过期、确认和阻断分离；枚举翻译只做文案映射 |
| 金额/数量/日期格式化 | `api.js`、`utils.js` 及页面局部函数 | 显式零与 null 不混淆；输入十进制字符串精度不变；格式化不计算收益或汇率 |
| 图表 | Chart.js、穿透/归因的 SVG/HTML/布局函数 | 坐标、图例、tooltip、交互可复用；序列、比例、分类、风险结论来自 API |
| 导入编辑器与底部操作区 | `account_import.js`、`account-import.css` | 文件只读/映射、截图逐图确认、手动草稿、脏状态、版本冲突和发布禁用；保持独立流程 |

状态组件先整理“输入字段 → 文案/色彩/操作”的映射，不能反向由颜色推断业务状态。共享组件提取需列出全部调用页面；未提供的 API 字段呈现缺失状态，不能在组件中补金融公式。

## 样式现状与迁移顺序

当前存在公共源样式、构建生成的手机样式、页面 CSS 和 HTML 内嵌 CSS。投资/更多使用手机派生样式；收支、账户、数据诊断、导入使用基础样式。不能简单把全部页面切换为同一套 CSS 来完成“统一”。

| 样式位置 | 职责和影响面 | 整理方法 |
| --- | --- | --- |
| `style.css` | 历史全局与业务规则，约 1.5 万行 | 先按页面/组件建立选择器归属；保留加载顺序、媒体条件和覆盖关系，不按文本相似批量删除 |
| `design-system.css` | token、外壳、共享组件覆盖层 | 保留在基础样式之后加载；避免把业务特例升级为全局覆盖 |
| `style-phone.css`、`design-system-phone.css` | 构建产物，由 430px 虚拟宽度规则生成 | 修改源文件/转换工具后验证产物；不手改产物；源样式变化同时检查手机派生调用方 |
| `holding-sync.css`、`more.css`、`account-import.css` | 持仓同步信息、更多、独立导入的局部规则 | 保持页面作用域，避免污染其他页面或全局按钮/折叠样式 |
| HTML 内嵌样式 | 收支约 489 行、账户约 206 行、数据诊断约 89 行 | 先逐页原样外移并保持层叠位置，再单独评审去重或视觉调整 |

上述规模仅用于识别耦合位置，基于 `9d510987bb9136d35cc8c97f2c1a8a03b9b07f35` 的源码统计；代码变动后重新核对，不将行数作为质量或性能指标。移出 CSS、删除旧规则、调整视觉分别审阅；不能用一次“清理”掩盖三种变化。

## 固定测试数据与交互验证

候选验证可以选择现有 API 或合成固定响应。固定测试数据必须由测试拦截/隔离候选环境注入，生产客户端不得在接口失败时自动切换为 fixture，也不能把一页中的真实金额与测试金额混作同一组合。

- 每组 fixture 保存来源为“合成固定测试数据”、对应 endpoint/参数、契约版本、业务日期/时区、账户/币种范围、内容哈希及用途；截图/演示明确标注“固定测试数据，非真实资产”，运行产物不得含原始账单或凭据。
- fixture 直接提供明确的响应数值和状态，不在测试适配器重新实现收益、NAV、分类或风控算法。布局证明和固定响应绑定证明分别记录；均不替代生产财务核验。
- 关键状态覆盖：普通证券、基金预估/确认、负现金/融资、平仓、多账户、长文本/大金额、零/null/缺字段，以及加载、空结果、失败、过期与阻断。
- 涉及布局/公共样式/导航时覆盖 320、390、1280 视口及受影响页面的完整交互；涉及持仓详情时按工作流程完整遍历对应数据集。固定字体、浏览器版本和前端包指纹，记录脚本错误、横向溢出、焦点和实际操作数。
- 导入覆盖返回、逐图确认、修改后失效、文件映射、手动草稿、冲突及发布关闭。只做前端验证时拦截写请求；需验证真实写入语义时使用另行准备的隔离 API/数据库，不能操作生产资料。

现有回归入口位于 `tests/frontend/`：静态契约、投资手机布局、启动/加载、持仓同步、收益日期/汇兑、穿透、更多、待处理和导入流程。浏览器可选用例的依赖/环境未满足时应记为跳过，不能用 pytest 总数替代可见验证。

## 分批实施与验收

以下是按依赖排列的拆分原则，不是已完成状态或合并/部署授权；实际范围、分级和结果记录在各自中文 PR。

1. 文档和契约梳理为 S 级：核对六页、调用方、样式来源、接口语义及原工作区差异；做引用/Markdown/差异检查，现有 CI 按原 workflow 自动执行。本阶段不手动重跑业务测试、浏览器或构建。
2. 单模块的纯展示辅助整理按影响定为 S/M 级：先固定当前响应和交互，再提取转义、格式化或状态映射；不得改变金额、默认值或业务语义。传输缓存和导入客户端各自保留行为。
3. 页面 CSS 外移与局部交互整理分开提交：逐页保持选择器/层叠/资源版本，验证该页面全部模板和关键状态，其余资产页面做轻量 smoke。
4. 公共组件、全局样式或跨页代码组织变化按 L 级单独 PR：列全调用方，执行相应完整布局/交互及必要保留回归。不得借整理恢复退役入口或删掉资产能力。
5. 依赖后端结果的历史公式替换必须先完成 [字段与语义提案](PAMS_PAGE_BOUNDARY.md#接口变更提案的字段模板)，后端提供契约后逐项绑定。固定输入中的金额/收益/状态差异逐项解释，不能为对齐而前端补差。

每项在最终 head 核对 CI；新 head 使旧 CI 不再代表最终结果。候选构建、页面技术验证、线上财务核验及用户验收分别成立，合并和部署继续遵守用户当前授权。
