# PAMS 前端设计系统收敛 v4：灰阶设计与重构方案

本文件定义 PAMS 前端后续改动的视觉边界与迁移方案。以用户在 2026-10-31 本对话确认的灰阶资产 App 风格为设计依据，收敛移动端 dark app 的组件契约。设计方向确认不等于具体页面验收；以下目标不代表代码已实现。实际开发、CI 和发布状态只记录在关联 GitHub PR。

统一外壳规则：`app-shell.css` 只负责外层 430px 居中视口与唯一主导航，`page-shell.css` 负责内容文档的边界及统一二级导航。业务页不再各自创建底栏；投资与收支二级导航共用尺寸、对齐和选中态。旧全局业务样式仍保留，其他冗余按模块另行整理，不能把本轮外壳收敛描述为全部样式已完成重构。详见 [外壳与内容页](PAMS_PAGE_BOUNDARY.md#统一外壳与内容页)。

## 设计定位

PAMS 是个人资产控制台，不是营销页。界面应优先服务三件事：

1. 快速判断资产状态。
2. 明确数据口径和更新时间。
3. 支持进一步下钻，而不是在首屏堆满解释文字。

视觉关键词：

- 精致、克制、金额优先；摘要舒展，列表紧凑。
- 参考用户喜欢的币安资产信息组织及深色 iPhone 黑灰白层次，不引入其品牌强调色。
- 黑色背景、深灰核心面板、白色主文字和灰色辅助文字。
- 仅盈亏数值和重要风险提示保留业务颜色；导航、按钮、普通状态采用灰阶。
- 大卡片只用于核心状态区；普通列表、设置入口和检查项使用紧凑行。

## 样式分层

共享变量已从历史样式迁出，外层与内容页加载同一份 tokens；保留基础/手机派生样式的构建路径。当前职责：

```text
tokens.css                 唯一变量源，外壳与六页都最先加载
app-shell.css              唯一主导航及外层视口
style.css / design-system.css
                           尚保留的业务规则、共享组件与密度
pages/*.css / more.css / account-import.css
                           页面布局与独立工作流
page-shell.css             内容边界及唯一二级导航，内容页最后加载
```

基础与手机派生样式仍遵守原相对顺序：`design-system.css` 必须在带版本号的 `style.css?v=...` 后加载。迁移的组件须同时移除或隔离旧定义；最终分层见下文，不将页面业务布局继续塞进共享覆盖层。

正式页面的 `<body>` 保留 `app-shell` 兼容类。主导航由外壳唯一持有；`ui.js` 中历史导航增强须核对调用后清理，预加载另行评估。设计系统基础样式不能依赖 JS 执行后才生效。

## 页面骨架

正式页面只保留三类主入口：

- `investments.html`：投资。
- `ledger.html`：收支。
- `more.html`：更多。

低频页面从“更多”进入：

- `accounts.html`
- `data_sources.html`

页面结构应保持一致：

```text
底部主导航
  -> 页面内二级导航 / tab
  -> 核心状态区
  -> 主列表 / 图表 / 检查项
  -> 点击后底部浮层或详情
```

不要恢复大 hero、状态栏大按钮、同步大入口条或旧独立风险页。低频工作台页面如果需要页面说明和快捷入口，使用 `.appWorkHeader`；不要恢复或新增 `appPageHero` / `appHero*`。

## 组件契约

后续新增 UI 时优先复用这些现有类或它们的语义：

- 面板：`.card`、`.investmentPanel`、`.portfolioRiskCategory`、`.portfolioRuleNode`
- 列表行：`.ledgerListRow`、`.syncCenterRow`、`.moreRow`
- 状态标签：`.statusBadge`、`.tag`、`.statusChip`、`.flowTag`
- 操作按钮：`.btn`、`.ledgerActionBtn`、`.reviewBtn`
- 工作台头部：`.appWorkHeader`、`.appShortcutGrid`、`.appShortcutCard`
- 底部浮层：`openBottomSheet`

新增页面如果需要新的卡片或列表，应先判断是否能复用上述结构。不能为了单页视觉效果新增一套完整组件。

## 移动端密度

移动端优先规则：

- 一屏先展示状态，不展示说明书。
- 列表行保持可扫读，标题、金额、状态三要素优先。
- 长解释进入详情或折叠区域。
- 热力图单元格优先展示标的名称和核心金额，完整解释放点击浮层。
- 交易、风险、配置页允许高密度，但必须有清晰点击入口。

## 前端保留与最小改动规则

### 前端保留边界（不代表版本已验收）

投资页、收支页、更多页、风控页已经是移动端 dark app 风格。不要因为数据问题重做 UI。

硬规则：

- 底部移动端 nav 只能有：`投资`、`收支`、`更多`。
- 不要恢复旧的顶部 `statusbar` 到收支页和风控页。
- 不要恢复旧的多按钮入口条，例如同步、口径、风控一排大按钮。
- 交易页手动录入和筛选是折叠按钮入口，不要恢复成常驻大表单。
- 交易明细默认显示前 10 单，通过“展开更多”显示全部，不要显示“最近10单”冗余标签。
- 前端组件只展示 API 结果，不能在多个 JS 组件里重复实现行业、主题、地区、币种、资产类型分类。

相关回归测试优先看：

- `tests/frontend/test_frontend_static_contract.py`
- `frontend/public/investments.html`
- `frontend/public/assets/js/transactions.js`
- `frontend/public/assets/js/ui.js`
- `frontend/public/assets/css/style.css`

### 前端改动最小化

除非用户明确要求 UI 改造，否则：

- 不新增大段 CSS。
- 不改颜色、圆角、阴影、页面密度。
- 不重排页面主结构。
- 只做字段绑定、文案修正、数据质量提示、缺失列表或必要交互修复。

若确实需要改 HTML/JS：

1. 先确认当前页面已有结构。
2. 只改对应模块。
3. 加静态契约测试。
4. bump JS/CSS 版本号。
5. 验证候选构建；生产 `pams-web` 的重建/切换须另获部署授权。
6. 按 [工作流程第 0.2 节](DEVELOPMENT_WORKFLOW.md#02-测试验证分层抽样与证据复用) 选择页面范围，在候选环境及获准部署后进行对应可见验证。

## 构建生成的手机样式

投资页和更多页使用构建生成的 style-phone.css、design-system-phone.css；源文件与转换工具位于 frontend/public/assets/css/ 和 frontend/tools/mobile_styles.py。文档中的基础样式示例不要求把当前页面改回旧引用。页面职责以 [页面边界](PAMS_PAGE_BOUNDARY.md) 为准；实际样式使用须核对 HTML、Dockerfile 和生成工具。

更多页沿用投资页的字体、背景、主文本和手机留白变量；使用紧凑列表，高级工具默认折叠，待处理入口按数据状态显示。更多页局部样式放在 more.css，限制于页面作用域，不在导航组件计算财务数据。验证应覆盖手机和宽屏、正常与异常状态、折叠交互、键盘焦点和横向溢出。


## 更多页的视觉与验证细节

更多页与投资页共用系统字体、背景、文本及留白变量，不另加字体、CDN 或独立主题。一级菜单目标为 16px、500–600 字重，二级工具 14px；替换历史 900 字重，不恢复顶部重复“更多”标题。辅助信息和分组标题保持较弱层级。使用平铺列表和细分隔线，不把资产数值大字号、等宽字体或收益红绿移植到普通菜单。

手机内容宽度及水平留白与投资页一致；高级工具默认折叠，展开只改变相关控件状态，不改变其他菜单的文本色。更多页局部样式限制在 `body.page-more`，不借局部修正改动全局折叠、投资或收支页面样式。

涉及该页面布局或共享样式时，按工作流程选择手机及宽屏覆盖；需要完整布局验证时覆盖 320、390 和 1280 视口、长标题、正常与异常状态、展开/收起、键盘 Tab/Shift+Tab 焦点与横向溢出。固定 DTO、禁网替身或模拟浏览器结果只证明对应候选，不代替真实设备、运行版本及财务核验。

## 已确认的设计选择与候选参数

用户已确认：最大 430px 居中、小屏自适应；黑灰白界面；核心摘要深灰面板、列表融入黑底；系统字体、正文常规字重、主金额放大且适度加粗；底部文字式导航，选中白色、未选中灰色；二级导航以短白线标记；面板约 16px、按钮约 10px 圆角；红绿及警示色仅用于盈亏和重要风险。

下表为落实方向的候选参数，具体色值、字号与间距须用真实长度的固定内容验证，不能登记为用户已验收页面。实际值以 `tokens.css` 为唯一实现源；下表为设计范围。保留既有红绿涨跌约定，不在视觉重构中倒置其语义。

| 类别 | 候选值 | 用途及限制 |
| --- | --- | --- |
| 底色 | `#000000` | 外壳和内容页同底色，去除蓝色偏色 |
| 面板 / 浮层 | `#1C1C1E` / `#2C2C2E` | 核心摘要与浮层分层；普通列表不逐行装卡片 |
| 主文字 / 辅助文字 | `#F5F5F7` / `#A1A1A6` | 白色表示重点与选中，灰色仍须清晰可读 |
| 分隔线 | `#38383A` | 细分隔，不形成密集网格；不能作为控件唯一可识别边界 |
| 字体 | 系统 UI 字体栈，兼容 PingFang SC / Microsoft YaHei | 中文和英文自然衔接；金额使用 tabular-nums，避免全站等宽字体 |
| 字号 / 字重 | 辅助 12/400、正文 14/400–500、标题 16/600、主金额 28–32/600–700 | 单位与数值分层；大金额优先换行或调整布局，不隐藏尾数、不新做金额缩写 |
| 行高 | 正文约 1.5，金额约 1.2 | 长名称、多行备注不得与金额重叠 |
| 间距 | 页边 16px；内部 8/12/16px；分区 24px | 320px 下必要时页边降为 12px，外壳与内容保持同中心线 |
| 圆角 | 面板 16px、按钮 10px、浮层顶部 16px | 普通列表无圆角背景，避免层层卡片 |

不使用装饰性渐变、发光、彩色导航或额外主导航图标。盈亏颜色继续来自业务含义，格式化组件不推导风险等级。常规界面保持灰阶；账本收支趋势、分类饼图与排行条按收入绿、支出红、净流入蓝恢复数据系列颜色。其他图表可使用中性序列，通过线型、点型、直接标签及可聚焦图例区分，不删除数据或下钻。

## 公共组件的目标契约

组件名称是职责示意，不要求引入框架或一口气创建全部文件。先复用现有语义与交互，再逐项替换实现。

| 组件 | 结构与外观 | 行为与边界 |
| --- | --- | --- |
| 主导航 | 三等分文字入口、白/灰选中状态 | 全应用一个实例；切换、返回、刷新仍正确，无位置漂移 |
| 二级导航 | 投资五项、收支三项共用高度和短白线 | 不用胶囊底块；沿用实际导航/面板语义，补齐焦点和可访问名称 |
| 核心摘要 | 深灰面板、主金额、少量辅助指标 | 显示 API 的日期/质量；缺失显示“—”及原因，不补零 |
| 列表行 | 左侧名称/说明，右侧金额/状态，细线分隔 | 长名称可换行；交互区域清晰；普通行与可点击行语义分开 |
| 金额 | 统一精度、符号、币种、对齐与空值展示入口 | 保留接口和既有精度契约，不计算收益、FX、NAV 或跨账户合并 |
| 按钮/状态 | 中性灰阶，明确可用、禁用、忙碌与焦点 | 风险提示同时带文字/图标；禁用原因可读；不因加载状态自动重试写入 |
| 图表容器 | 统一图例、坐标、提示框和加载/空/错状态 | 只绘制 API 序列；保留下钻、数据日期和口径说明入口 |
| 底部浮层 | 深灰背景，统一标题、关闭与内容间距 | 焦点进入/返回、Esc、滚动锁、手机键盘及安全区需验证 |

常用点击目标候选最小 44px；正文对比度以 4.5:1、控件及焦点辨识以 3:1 作为候选验收目标，逐状态实测。白色键盘焦点与选中短线区分；不只依赖颜色表达风险。保留系统缩放，尊重减少动态效果设置，不增加自动入场动画。

## 页面编排与功能保留

```text
同一 430px 应用外壳
  内容视口
    二级导航（投资 / 收支；更多不添加空导航）
    摘要与当前内容
    详情 / 浮层 / 工作流
  常驻主导航：投资  收支  更多
```

| 页面 | 目标编排 | 必须保留 |
| --- | --- | --- |
| 投资 | 持仓/分析/交易/风险/配置同层；摘要突出金额，列表保持紧凑 | 持仓详情及分类视图、穿透/归因切换、交易折叠录入与筛选、前 10 单及展开、风险和目标配置 |
| 收支 | 总览/流水/账户同层；摘要之后趋势与排名纵向排列 | 时间筛选、流水筛选及详情、账户访问；不恢复已删除页头四项 |
| 更多 | 无重复大标题；入口列表、待处理状态、高级工具折叠 | 导入、账户、数据源和既有资产工具可达，异常和无异常状态均正常 |
| 账户 | 紧凑工具页头部、账户列表及详情 | 余额、银行对账、资金流转匹配；删除收支快捷链接不等于删除功能 |
| 数据源 | 同步/覆盖/质量状态统一成列表与详情 | 原有状态查询及显式操作；不新增自动刷新写入或修改默认开关 |
| 导入 | 步骤与当前核对内容优先，操作区避开底栏及键盘 | 文件/截图/手工流程、暂存/预检/发布区分、权限/能力、revision 冲突及离页保护 |

视觉迁移不变更默认排序、分页范围、账户筛选或金融值。每页实施前以调用点和固定响应建立字段/入口清单；页面设计必须覆盖正常、空、加载、失败、过期和部分缺失状态。合成 fixture 在预览入口显式标注，不能出现在生产数据入口冒充资产事实。

## 样式迁移方法

目标顺序为“设计变量 → 基础排版 → 外壳 → 共享组件 → 页面布局”，每类组件只有一个样式所有者。CSS 文件可以按此分层，业务页只布局，不再重定义共享组件的字体、颜色和选中态。外层与 iframe 内层加载同一份变量源，不能各维护一套调色板。

1. 列出待迁移组件的所有选择器、内联样式、脚本动态样式及调用页，记录固定数据的迁移前截图和交互。
2. 第一批抽出共享变量，保留旧变量别名；迁移主/二级导航、摘要、列表、金额和状态的明确规则。每类组件替换时在同一 PR 删除对应旧定义，暂未迁移规则限定在旧页面/旧组件作用域。
3. 不在文件末尾再追加全局高优先级覆盖，不盲目移除 `!important`。若使用 CSS layers，须先处理未分层旧规则优先于分层规则及 important 顺序反转的问题，不能仅把新规则包进 layer。
4. 将收支、账户、数据源的内嵌 CSS 按上述归属迁出；动态模板和详情浮层调用方一并核对。禁用状态、打印/响应式及罕见详情未验证前不凭搜索无命中删样式。
5. 手机生成样式暂保持现有构建链；在基础样式已经 mobile-first 且全调用方通过验证后，再单独移除转换依赖和冗余规则，不直接删除生成工具或更改视口语义。
6. 每批更新受影响资源版本；记录删除/保留的规则及原因。冗余减少以所有权清晰、旧定义退出和行为回归为依据，不用行数下降替代验证。

## 实施批次与验收门槛

这是依赖顺序与完成条件，不是进度台账；授权、执行和 CI 状态归各 PR。本轮方案为 S 级纯文档，后续实施重新按实际影响分级。

| 批次 | 产物及边界 | 分级与退出条件 |
| --- | --- | --- |
| A：灰阶基础与核心组件 | 同源 token、系统字体、导航、摘要、列表、金额、状态；先用投资/收支/更多合成数据预览，随后覆盖所有调用页 | L，独立 PR；全局影响页双视口完整回归，持仓详情受影响时遍历完整对应数据集；视觉样稿交用户确认 |
| B：页面布局与旧样式退出 | 按投资、收支、更多/工具页分别迁移；每页旧定义与新定义同步替换 | 页面内样式通常 M，共享或跨页面联动升级 L；布局、字段、入口与状态覆盖，不混入金融计算调整 |
| C：模块与状态职责 | 拆大模块，隔离请求/状态/渲染/事件，补初始化与清理契约 | 架构改动 L，按业务域独立 PR；重复进入无重复监听/请求/图表，写入流程不被自动重放 |
| D：应用容器 | C 完成后评估逐页替换 iframe；唯一导航、深链、返回、状态恢复和离页保护统一归外壳 | L，独立方案及 PR；未满足迁移门槛保留 iframe，不与首轮换肤同时实施 |
| 接口协作：独立依赖 | 盘点历史金融计算与缺失字段，待后端契约落实后逐项绑定替换 | 与 A/B 分离；影响收益/归属等按 L；固定输入字段级对照，禁止前端临时补算法 |

先完成 A 的视觉与公共基础，再逐页 B；C 可以在对应页面保留回归明确后开展，不与同一文件的大范围视觉编辑交叉。D 依赖模块生命周期与状态契约，不强制为重构引入 React/Vue、打包器、TypeScript 或新全局状态库；工具链调整另列收益与迁移成本。

每批验收均包含：受影响功能保留、320/390 手机与 1280 宽屏布局（需要时补 926 复现视口）、键盘/焦点/缩放、无横向溢出、长文本/大金额/null/负现金/融资/平仓/多账户/基金预估确认状态。固定测试数据的金额和语义前后应一致；生产实时财务对照按获准发布流程另做。测试失败记录根因，不能删除断言换取通过。

最终 PR 必须核对其最终 head CI，非文档实施按工作流程完成静态/定向/全量、相关候选构建与 smoke。涉及全局 CSS/字体/导航时不得只检查首屏或三个主入口。合并、部署、财务核准、用户验收分别记录；只更新获准受影响组件，撤回仅限对应代码/样式，不恢复数据库或覆盖其他对话修改。


## 灰阶图表与验证入口

`assets/js/shared/chart_theme.js` 读取同一 CSS 变量，将画布不能直接处理的 custom properties 转为绘制颜色；分类 palette 只用于视觉序列顺序，不成为分类事实。投资、收支、穿透及通用图表使用该主题；多线收益图同时采用虚线/点型，分类图保留文字排名与原有下钻。原业务序列、金融计算、金额和 API 路径未因换色变更。

`tests/frontend/test_gray_design.py` 检查变量/样式所有权和主题行为；现有手机转换测试保留媒体条件、规则顺序与确定性，替代旧整文件哈希冻结。既有金额/日期/FX/导入等回归保持语义断言，版本参数与样式迁出位置随实现更新。实际回放和发布结果归对应 PR，固定响应验证不等于生产财务核准。
