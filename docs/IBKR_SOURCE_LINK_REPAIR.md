# IBKR 来源关联修复工具：审批与隔离演练

## 当前边界

本版本仅提供默认只读预检和**带审批的隔离库演练**。不支持生产执行，
没有 `--apply`、`--force`、HTTP 写入入口或调度注册。合并、部署、审批文件都不构成生产修账许可。
不改变金额、份额、成本、现金、费用、收益率、NAV、持仓、原始 JSON 或布局。

工具：`scripts/ibkr_source_link_repair.py`，在 API 镜像之外。
复用现有报告选择、来源预检、费用证据和离线映射规划，不另写解析或金额算法。
迁移文件 `database/postgres/schema/070_ibkr_source_link_repair_audit.sql` 本轮只在隔离库应用，
CLI 不自动建表。生产预检在该表不存在时也可工作。

## 输入与输出

| 步骤 | 输入 | 输出/保护 |
| --- | --- | --- |
| 默认预检 | 显式 `PAMS_REPAIR_DSN`、`--raw-dir`，数据库已发布报告及完整来源/fact | 服务器 READ ONLY/REPEATABLE READ；审批包和哈希，不写审计或业务表 |
| 审批 | 完整审批包哈希、审批人/依据、带时区有效期、全部风险确认 | 最长 24 小时，只能批准隔离演练；缺失、过期或范围不符拒绝 |
| 隔离演练 | 原审批包/审批文件、显式测试服务器、随机库名和数据库标记、已建审计表 | 事务内重新推导全批次，只改外层 source_id，并原子写入审计 |
| 重复执行 | 原审批仍有效、同一审计和完整已应用状态 | 更新 0 行，不重复插入审计；部分应用、缺审计或审计不符拒绝 |

审批包绑定服务器/库/数据库操作角色、报告 SHA/业务日/发布 run、完整来源与 fact 指纹、
保护列指纹、投影后全行指纹、逐条旧/新 ID、占用环/链及风险。
不能跨库复用、删掉阻断后重签哈希、只批准批次的一部分或在原文变化后继续执行。
新鲜底稿与审批包分别保留在私有证据目录，不将交易、凭据或审批人个人信息提交 GitHub。

## 使用顺序

先人工确认目标环境、保存底稿。`PAMS_REPAIR_DSN` 不回退到应用的 `PG*` 凭据。
推荐预检使用具备所需 SELECT 权限的只读角色，不在命令行粘贴带密码 DSN。

```powershell
# 显式环境变量由操作者在当前会话安全设置，不在报告打印凭据。
python scripts/ibkr_source_link_repair.py --raw-dir <有效Flex原文目录>
```

标准输出 JSON 的 `request` 对象是审批包。`executable=false`、
`production_write_supported=false`，即使资料完整也不是生产批准。
仅隔离环境允许下面流程：

1. 从固定底稿恢复独立 PostgreSQL 副本，使用名称 `pams_ibkr_tx_test_<32位随机hex>`。
2. 显式设置 `PAMS_TEST_POSTGRES_DSN`，连接的 host/port/user 必须完全匹配该测试服务器。
3. 人工核对后在该隔离库设置数据库 comment `pams-isolated-lineage-rehearsal`，应用 070 迁移。
4. 在该库生成预检审批包。审批文件只允许下列字段，`accepted_risks` 必须与包内列表完全一致：

```json
{
  "purpose": "isolated_source_link_rehearsal",
  "request_sha256": "<审批包完整哈希>",
  "approved_by": "<明确审批人>",
  "reference": "<仅隔离演练的授权依据>",
  "issued_at": "<带时区ISO时间>",
  "expires_at": "<最长24小时的带时区ISO时间>",
  "accepted_risks": ["<审批包原风险列表，不删减>"]
}
```

5. 显式调用，结束后核对业务不变量、审计记录和重复执行结果：

```powershell
python scripts/ibkr_source_link_repair.py --raw-dir <有效Flex原文目录> --rehearse --request <审批包.json> --approval <审批.json>
```

审批文件是带归属的人工声明，不是签名、认证服务或防数据库管理员篡改的证据。
测试库保护也不是抵御管理员恶意仿造环境的安全边界。本版本故意不开放生产模式。

## 原子性、审计与回滚

- 新鲜非 autocommit 连接；先只读核对隔离标记，再开启写事务；不提交调用者的已有事务。
- 锁定 fact、来源、报告发布记录和审计表，重推完整计划；先唯一临时 ID，再目标 ID，兼容占用环。
- 审批在校验后、实际更新前及写审计前检查有效期；保护列和投影后整行指纹必须完全相同。
- 成功才写 `pams_ibkr_source_link_repair_audit`，包含完整审批包/审批、哈希、映射、数量、角色、时间。
  CLI 不更新/删除该记录；表所有者仍有管理权限，不声称数据库级不可篡改。
- 中断、唯一约束、其他字段副作用、审计失败、提交失败都回滚本事务，不能留下“已应用”的假审计。
  拒绝/失败输出结构化状态和异常类型，不输出原始异常中的凭据。提交响应不明时标记未核准，
  只在原审批有效且全状态/原审计一致时重试确认，不盲目再写。
- “回滚验证”指失败事务回滚；**不提供已提交批次的反向修复命令**。
  已提交后回退必须重新取证、核对后续变化并另行审批，不能回灌生产数据库凑相等。

## 验收与保留风险

隔离演练覆盖全部 43 条映射/41 条目标占用、首次 43/重复 0、故障回滚及一次审计；
九组财务输出、保护列、非 IBKR fact 和其他八表必须不变。
生产另做新鲜九表/九接口只读比较，不用副本结果代替生产验收。
CI 使用 pytest 原生结果、现有静态检查/构建和 GitHub 运行记录，不另造验证框架。

历史内嵌 source_id 是保留的原始证据，隔离修正外层关联后仍可能被旧检查提示；
不能改写原文或清除旧警告来凑全绿。费用 scalar 未建模币种、单笔现金结算、历史覆盖、
全账户 NAV/收益核准仍是独立未决项，审批来源关联不会自动核准这些风险。
