# IBKR 来源关联安全修复预演

本功能是离线诊断与隔离实验，不是生产修复器，不接入 endpoint、调度或页面。生产保持只读，原预检和费用阻断不变；实验通过也不代表金额/历史/费用或用户验收已通过。

## 输入和输出

- `services.ibkr_lineage_rehearsal.plan_rehearsal` 输入同一已发布 Flex 的原文/哈希/质量、完整来源行和该来源表的完整 fact。复用既有来源预检与费用取证，不在本模块重写金融公式。
- 原文 SHA256、实际与应有报告日期必须一致；过期/legacy、缺失、重复身份、数值或历史证据冲突、全量范围不完整均拒绝。当前上限 500 行，超过时明确阻断，不将截断页当完整批次。
- 输出逐条 fact/稳定键、旧/新 ID、目标占用者和环/链/空闲目标组件；包含完整来源、事实、非 source_id 字段和投影结果的确定指纹。保留重复行，数值不做浮点近似或金额换算，哈希仅用于输入一致性，不是签名或授权。
- 占用者必须同属本批次且目标唯一；批次外占用不能逐条覆盖。费用原文/内嵌及数值证据不足时不能预演；证据足够也只允许隔离实验，不解除 scalar fee_amount 未独立建模币种的警告。
- 始终 `simulation_only=true`、`executable=false`、`production_write_supported=false`、`production_repair_ready=false`。`ready_for_isolated_rehearsal` 仅表示可在 scratch 副本试验，不表示可生产修复。

## 隔离实验

写入辅助仅在 `tests/ibkr_rehearsal_support.py`，不打入 API 镜像，不创建连接或接受生产执行请求。调用者须提供与显式 PAMS_TEST_POSTGRES_DSN 的服务器/用户一致的连接、随机 disposable 库名和隔离数据库标记；普通应用数据库名被拒绝。这些是防误用门禁，不是面对恶意数据库管理员的安全隔离保证。

1. 开事务并锁定事实与来源表，重读完整数据；核对报告/规划指纹、来源及全部非 source_id 字段、稳定键对应的真实目标。缓存旧规划不能覆盖输入漂移或并发写入。
2. 在同一事务内先赋唯一临时 source_id，再统一赋最终 ID，处理不可延迟唯一约束下的环和链；不禁用约束，不删除/重建事实，不修改其他列。
3. 提交前核对完整投影行指纹。中断、锁冲突、额外字段变化或提交期约束失败均回滚，临时 ID 不留存。
4. 相同规划再次执行，若来源、全部保护字段与完整最终行一致则返回 0 更新；混合/部分完成或输入变化拒绝，不猜测恢复进度。

生产没有执行入口，也不把现有预检的 target_id_in_use 改为已解决。未来若需要真正执行，须独立授权和新底稿，并另行解决审计兼容及剩余阻断。

## 重要发现：历史 ID 不能静默覆盖

当前 fact.raw_json.source_row.source_id 保留原入账时的 ID。只修改外层 source_id 后，现有预检会报告 embedded_evidence_mismatch；这是预演必须暴露的结果，不是靠改历史 JSON、source_hash 或删除旧校验消除的噪音。

真实底稿实验的结构为一个 41 条占用环和两个空闲目标，合计 43 条映射。只改外层 ID 可让物理关联错配归零，但会出现 43 条历史证据 ID 提示，并保留 10 条费用币种提示。因此当前结论为“隔离结构试验通过、生产修复仍未就绪”，不是可批准执行清单。

## 审计证据解释（不替代原阻断）

规划新增 `audit_evidence` 子结果，原 `projected_after_counts` / `projected_after_reasons` 与所有执行标志不变。解释的是完整底稿的确定投影，不是自动放行生产现状。

- `complete_scope` 要求原文、来源及 IBKR fact 的稳定键多重集合完整一致且唯一；分页或费用截断不能当完整证据。缺失、重复、报告或金额冲突仍按旧预检阻断。
- 仅允许映射内的 `embedded_evidence_mismatch.field=source_id` 解释为 `historical_reference_preserved`：内嵌 ID 须等于底稿旧值，投影外层 ID 与稳定执行对应目标相同，其他字段/哈希/原文全部保留。执行编号、账户或其他历史字段冲突不能借此消除。
- 费用只在 `unit_review.status=source_unit_verified` 时区分其来源单位证据，仍保留 `fee_currency_not_modeled` / `individual_cash_settlement_unverified`。旧费用警告不删除、不再扣费、不宣称单笔 NAV 已核准。
- `review_rehearsal_evidence(baseline, plan, projected_facts)` 从原始完整底稿重建规划并核对整个投影指纹；缺底稿、部分完成、原始 JSON/时间戳/金额变化、调用者自行重算哈希的篡改规划都拒绝。返回副本，不修改输入或连接数据库；异常仅输出安全类型。
- 指纹不是授权签名，也不证明调用者提供底稿的外部真实性；底稿来源、保管与用户审批必须独立保留。真实修复后若无可证明的原底稿/映射，不能仅凭当前字段相似自动认可历史 ID。
- 即使 `unresolved_evidence=0`，状态仍为 `review`，`production_repair_ready=false`；人工审批、费用持久模型/现金结算、历史覆盖和全账核准不被替代。生产仍有真实物理错配时，该问题及批次占用保护不因投影解释而消失。

## 证据和边界

- 单元及真实 PostgreSQL 覆盖环/链、缺证据、缺币种、非法数值、输入/规划变化、稳定身份重定向、幂等、中断/约束/提交失败、并发锁及只改 source_id。
- 私有真实实验使用跨 schema 的恢复副本，明确保留 PAMS 财务资料与收益所需行情子集，不复制全库或把视图定义当完整底表备份。先确认恢复依赖和数据校验；不完整的失败导出不得登记可恢复。
- 金融输出前后使用新进程、同一冻结行情输入重新运行九组 GET，生成时间单列。全部非 source_id 字段及其他核心表必须相同，不以应用缓存凑相等；行情录制范围和未恢复资料另列。
- 生产九表/九接口新鲜只读对照、页面轻量 smoke 与上述隔离实验分别记录，不能相互替代。既有前端/接口/公式/写入服务未变；不宣称预演解决全账户 NAV、历史覆盖或费用币种建模。
- 财务原文、逐笔身份与实际金额只留私有底稿；仓库测试用合成数据。独立中文 PR，不自动合并、部署或修账。
