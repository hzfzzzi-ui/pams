# IBKR 来源关联追溯与修复预检

## 责任与边界

新增 `ibkr_lineage_preflight` 只读服务和 `GET /api/ibkr/lineage-preflight`。回答“稳定执行身份与物理来源关联为何不一致、有哪些候选和阻断依据”，不修改资产事实或代替原对账。没有修复执行器、写入接口、自动 UPDATE、批量 SQL 或 schema 变化；现有页面和同步中心不接入新逻辑，旧接口字段/解析/调度/收益/NAV 公式不变。

输入为既有发布选源/哈希/质量状态、原 `parse_flex_report`、`pams_ibkr_trades` 和该表来源的 `pams_investment_trade_fact`，包括事实内嵌的 `raw_json.source_row`。不得扫描原文 mtime 选择新报告，也不读取实时价格或自行折算汇率。

## 预检顺序

1. 按稳定源键定位，并核查来源账户与官方执行编号的唯一性；原文、当前来源、事实任一重复或缺失均阻断。缺稳定官方执行编号不能批准候选，报告未覆盖的事实单列阻断，不猜测配对。
2. 对照账户/日期/标的/币种/方向，以及原币数量、价格、成交额、净现金；费用同币种才与原文比较，跨币种只提示，不转换/修正费用。缺值不补零，非有限值拒绝；容差复用既有 `1e-8`，差额为 actual−expected，数值输出十进制字符串。
3. 核对事实内嵌旧来源 ID、稳定键、官方执行/账户编号和历史数值；按既有 `make_source_hash` 规则验证源哈希。源哈希优先基于稳定键，本轮不重算/更新该字段，不覆盖历史 `raw_json`。
4. 检查目标物理 ID 的现有事实引用。目标被其他事实占用时，哪怕对方也在候选中，仍阻断逐条修复；不自动安排临时 ID、解除唯一约束或执行置换。
5. 报告过期、legacy、沿用旧值或账户不唯一时，保留追溯证据但阻断修复预检。没有记录也不能把全局来源问题显示为通过。

## 输出契约

- `offset>=0`、`1<=limit<=500`，默认 100。按稳定键/事实 ID 排序分页；`total`、状态计数和原因计数基于全量，不能沿用旧对账的 30 条样本当完整候选清单。
- 逐笔记录事实 ID、稳定键、旧/目标来源 ID、账户/执行/日期/币种、不变量及原值/差额、内嵌历史证据、旧 ID 当前指向及占用者。
- `proposal` 只描述 `source_id` 的 before/after，必须再次用户批准；不修改金额、份额、收益、NAV、FX、费用币种、源哈希或历史原文。
- `candidate` 仅表示当前证据无已知阻断，**不等于可执行或已批准**；`blocked` 表示一个或多个阻断；`unchanged` 表示关联相同且预检无阻断。全局及每条 `executable=false`、`repair_implemented=false`，没有任何执行能力。
- `link_mismatches` 与阻断行数分开；同一行可以有多项阻断，不能把原因计数加总当成错单数量。`unavailable` 明确表示缺表/缺报告/读取失败，`counts=null`，不能伪装零差异。
- 账户下的读结果属于私有财务诊断，不在 PR 上传原文、逐笔候选或数值底稿。未来修复必须重新取证，不可直接执行过期 GET 返回的候选。

## 本轮只读发现（2026-10-24 冻结底稿）

- 66 条来源交易和 66 条事实的稳定键一一对应；43 条物理来源 ID 不同。43 条内嵌旧 ID/稳定键/执行编号与对应记录相符，41 个旧 ID 现在指向别的交易、2 个已不存在；41 个目标 ID 已被其他事实占用。
- 43 条对应的事实创建于 6/4–6/5，当前来源行创建于 6/6。可证实的是“当前物理行较新而事实保留旧引用”；这支持历史来源重建/重导入假设，但没有操作日志，不能声称已查明具体命令、操作者或归咎当前自动同步。
- 当前源码 `_write_trades` 使用稳定键 UPSERT，不更新主键；真实隔离库重复 UPSERT 保留 ID。事实 backfill 的物理 ID 排除与 `ON CONFLICT DO NOTHING` 不会主动修正旧引用；稳定源键生成的源哈希也解释了为何没有新增重复事实。以上代码机制不等于证明历史上发生过哪个操作。
- 可比原币值和内嵌数值未发现差异；当时报告为 10/22、应有 10/23，66 条均被来源质量阻断；另有 41 条目标占用、10 笔费用币种问题。预检候选放行数为 0，不修账，不自动解除历史覆盖保护。

## 无写入与验证

专用连接首条查询前设置 PostgreSQL `REPEATABLE READ READ ONLY`，单 SQL 超时 5 秒，读取后再次校验发布内容 SHA256 并关闭连接。不调用 ensure、DDL、refresh、backfill、修复、审计插入或原文写入。异常仅返回安全类型，不包含凭据/DSN/错误正文。

隔离库验证服务器拒绝意外 UPDATE，业务/审计表和 XML 前后不变；覆盖唯一匹配、旧 ID 被复用、互换占用、重复身份、字段/金额异常、缺值/非有限值、过期/缺表/哈希变化、跨账户/币种、分页不截断和重复执行。生产前后底稿及现有页面保留验证独立记录，技术通过不等于全部历史资产已核准。
