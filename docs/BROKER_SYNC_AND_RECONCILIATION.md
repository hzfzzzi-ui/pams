# 券商同步与对账

本文描述隔离新库中的 IBKR 来源、事实和对账契约。现有线上服务与数据库未由本次重构切换；空库初始化不是存量数据库升级或历史回填。

## 报表与来源

Flex 同步按券商账户和报告业务日保存原始 XML、SHA-256、来源批次和逐项明细。交易与现金各自保留原币、业务日期及官方字段；缺失的数量、币种、税费或汇率不能用零、默认币种或其他日期的汇率填充。自动同步和独立现金同步可复用同一份原件，迟到汇率通过补充来源发布，不改写原有已发布证据。相同官方事件跨报表出现时，只有原事实与其来源核对通过才记录为未关联的重复观察，不自动制造第二笔事实或伪称多份来源已关联。

同一报表重放保持幂等；账户锁、来源锁、事实写入和发布处于受控事务。资料内容、身份或数值冲突时保留待核对或阻断，不覆盖原事实。账户、日期和原文字节需一致；报表缺段、缺字段或超出范围时不将其视为完整。

## 持仓和账户范围

持仓更新保留来源及不可变版本。同日更正与跨日变化不能覆盖旧证据；标的缺席不能自动视为清仓。明确零值退出需要同账户、同合约、已核对来源和完整范围，证据不齐时保持未知。证券身份和账户归属须有独立证据，symbol 相同、金额相同或来源内容一致本身不构成认证。

隔离来源审核支持显式核对券商账户与 PAMS 账户的映射，该核对绑定报告账户、业务日和原文哈希；身份认证仍为未知，账户映射不能代替完整范围证明。

账户净值需要能证明现金、证券及其币种范围和相应汇率。独立日结证据用于相应账户和业务日；缺账户映射、完整范围、原文或汇率时，净值和收益应保持未知或标注覆盖不足，不用部分证券或上一次金额冒充完整账户。 在无可选的平台、手工或账单主余额时，账户映射、原文哈希、独立日结全部分项和当日汇率均已核验的日结可作为主余额；应计利息与分红保留为日结估值分项，不生成持仓或现金。

## 手续费与收支

交易原始净现金与费用币种分开记录。手续费缺单位或不同于交易币种时，保留官方原币和净现金，费用汇总、成本或收益若无法计算则为未知，不把不同币种直接相加。费用审阅核对原始金额、币种与已关联事实，标出不一致或缺证据；这不证明券商身份、银行结算，也不发起额外扣费。外汇成交记录保留原文方向，换汇事实不自动证明两侧现金腿或结算。

现金事实以来源原文和业务日可用汇率核验；非人民币基准按同日汇率计算，缺少任一必要费率时保留原币并标未知。银行真实流水需独立来源和人工确认，券商派生记录不能仅按同金额冒充银行原件。

## 只读对账与运行

`GET /api/ibkr/reconciliation` 在服务器只读、重复读事务内校验已发布原件、来源明细及交易事实，并展示可核验的持仓候选和手续费审阅。缺表、缺报表、原件损坏、关联不明或身份未认证时返回对应待核对状态。对账不会创建表、改写事实或执行修复。

同步日期采用券商报表业务日与交易日历；仅在原件完整且发布成功后更新业务水位。隔离新库使用 `broker_processing_state`，按状态类型分别保存报表发布结果和现金事件待处理水位，包括来源、业务日、哈希与重试所需的输入指纹。读取时重新核验原文与状态指纹，无效证据不阻止重新排队。技术运行错误、堆栈和调度事件写入运行日志。

报告选源先比较业务日，同一业务日再比较发布版本；旧业务日的后续状态不能覆盖新报告。最新业务日原件损坏时可回退到可核验的旧报告，并标为待核对或过期；发布水位仍保留最新业务日，不能因此倒退。

技术运行结果通过脱敏结构化日志输出；异常只记录受限类型与代码位置，不记录原文、账户或异常消息。持久业务水位不等同于账户身份或财务核准。没有接入日志查询时，状态接口中最近一次技术尝试为未知；这不影响已验证的有效报表、日期和现金重试状态。独立日结的配置、启动条件及实际运行能力以 [配置来源](CONFIGURATION.md) 和对应代码为准；此处仅描述隔离候选，未切换线上。

隔离验证使用一次性数据库和合成报表，不读取真实账单；生产迁移、部署和财务验收均为独立步骤。
