# IBKR 自动化闭环与验收边界

## 已有责任及本轮连接处

不重建collector、事实模型、收益引擎、对账规则或调度框架。沿用现有日报确认journal，分别记录官方生产报告、独立日结发布、原币资金事实处理。三者成功互不替代。

| 链路 | 输入 | 输出 | 不允许的副作用 |
| --- | --- | --- | --- |
| 既有Flex同步 | 生产查询、已发布日及报表原文 | 交易、快照、发布状态 | 不把报告改标其他日期 |
| 日结自动发布 | 独立审计查询、既有批准manifest账户/期间、同日生产报告 | 不可变XML及原子manifest | 不写交易、资金或余额事实；不从未知线上状态自动批准初始范围 |
| 原币资金事实 | 已发布日结证据中的逐笔CashTransaction | 配置截止日之后的规范投资事实 | 不拿日汇总造单笔，不回填截止线及之前历史，不向已含入金的现金再加一次钱 |
| 展示绑定 | 后端同日账户字段及确认状态 | 原页面金额/收益率/状态 | 不借持仓收益率充当账户率，不把NULL转成0，不强行让现值等于旧日结 |

生产查询1526576的当前原文没有CashTransaction，不能靠给它增加解析分支宣称资金闭环。已批准独立日结查询1685405包含逐笔资金事件；其发布器仍保持facts_written=0，资金事实由独立步骤处理。查询及Token不改。

## 日结部署开关

- `PAMS_IBKR_DAILY_CLOSE_MANIFEST`沿用现有批准指针，不自动创建生产初始基线。
- `PAMS_IBKR_DAILY_CLOSE_QUERY_ID`必须是与生产查询不同的数字ID，默认关闭。
- scheduler `PAMS_IBKR_DAILY_CLOSE_SYNC_ENABLED`默认false，获准部署才启用。
- `GET /api/ibkr/daily-close/status`只读；`POST /api/ibkr/daily-close/sync`仅获取并发布证据，不能指定重标日期或对齐当前估值。
- 复用现有30分钟调度、OS互斥、持久意图、退避、重试后再读确认及失联响应恢复；使用独立`ibkr_daily_close`状态，不清除其他市场历史缺口。

同日已确认直接返回unchanged，不因生成时间变化替换原文。新日需同账户、完整日结与期间桥接、生产现金及持仓组成吻合、源字节未变化，并覆盖且不改写已发布历史。失败保留前一指针，不补零、不用旧数据宣称当日确认。报告更正触及历史时明确阻断，不能借自动化越过历史修账授权。

## 验收分类

- 代码验证：静态检查、固定输入完整响应、幂等/原文变更/限流/断线/互斥/原子发布与隔离数据库事务。
- 发布验证：候选和实际镜像身份；全部旧环境值及挂载保持，仅核准新开关变化；九表九接口新鲜对照，双视口页面验证。
- 正常业务Ready：来源可获取、任务自动运行、报表确认日期可推进、官方事件可自动入账且不会重复，错误留在后台状态，不要求用户逐次授权。
- 全历史财务核准：另行验证费用单位、来源关联、历史入金、日期汇率及完整历史，不由上述成功推断。
- 长期无人值守：需连续7个美股交易日实测；部署当天不能提前登记通过。主机必须常开，Token维护和源方数据发布时点不是程序可以消除的依赖。

保留pytest、Playwright原生报告及GitHub运行记录，不另建报告框架。部署记录归原功能PR中文评论，Git状态文档只记录带时间快照，不当实时控制面。
