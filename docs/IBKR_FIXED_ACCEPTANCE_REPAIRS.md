# IBKR 固定验收修复边界

本文件描述代码能力，不证明生产已经启用、修账或通过资产验收。固定范围仅为应计日结、完整持仓集合、入金闭环；不扩展到历史来源ID或费用核准。

## 1. 应计日结与期间收益

- 责任模块：`ibkr_daily_close` 只解析和证明；`ibkr_daily_close_read` 只读已明确发布的补充证据；performance、portfolio_state、valuation_nav 消费相同日结。旧解析器保留为兼容路径与回归对象，不把现金加证券重新标记成官方NAV。
- 日结恒等式：现金 + 证券 + 应计利息 + 应计股息 + 明确列出的其他NAV成分 = 官方日结NAV。分项/总项、Long/Short、子成分互相校验，不重复加总。已结算利息已经在现金中，不重复扣除。
- 期间盈亏：期末NAV − 独立期初NAV − 期间净外部流量。只接受完全同范围桥接，或连续、端点一致的逐日ChangeInNAV。未知字段/缺少工作日/缺期初不补零，不使用YTD入金替代任意期间资金流。
- 旧`return_ratio`字段保留为简单资本回报比：期间盈亏 /（期初NAV + 期间净外部流量），不是TWR、MWR或个股持仓收益率。分母不为正时无定义，不能伪造0%。持仓成本、数量、交易、原币现金不因应计调整而改变。
- 后端显式输出`return_capital_base/cny`，前端仅在新日结证明与展示FX均可用时直接绑定NAV、期间盈亏和该资本基数，不再用“证券＋现金”或“NAV－入金”覆盖新口径。未启用保留旧兼容路径；缺字段不把新口径零值化，无定义收益率显示`--`。HTML只更新模块缓存版本，不改布局、CSS、导航或交互。
- 官方账户基币NAV按内部同业务日汇率转换至展示基币；不使用未来汇率，不默认为1。原币逐项估值与账户基币再折算的FX差异单列桥接，不能混成投资盈利。期末USD盈亏乘期末汇率只是展示折算，不是人民币期间投资收益。
- gross assets/liabilities必须有官方总Long/Short证明，不能把净NAV按正负伪造成总资产/负债。归属比例只应用一次。历史缺日使用上一有效值时必须带原日、请求日、过期状态，不假称当日已确认。
- 旧的已发布估值不能仅靠相同XML身份覆盖当前结果：还须绑定实际汇率证据、归属比例和账户估值输入。最终NAV终点同样检查证明，避免合成层再次覆盖。持仓收益投影与NAV投影分开，不因修NAV顺带改变持仓盈亏定义。
- 完整券商performance字段保持完整账户语义，`portfolio_account`是只读组合身份/归属join的独立个人展示；未证明身份/FX/归属时不得启用新个人展示。归属在后端仅应用一次，0归属不显示虚构0%收益率。账户总览保留原平台原始值，仅将primary余额绑定共享确认值及历史折算值，旧审批按新证据失效。

### 证据发布与启用

`scripts/ibkr_daily_close.py` 默认只校验指定XML；显式`--publish-dir`仅发布不可变原文及独立manifest，不连接数据库、不导入交易或入金。可显式下载另一个审计查询，复用现有Token，不修改原查询。禁止把审计原文送入现有交易导入器。

消费者仅在显式配置`PAMS_IBKR_DAILY_CLOSE_MANIFEST`时读取该manifest；本轮不修改生产配置。manifest限定用途、账户映射、源账号、日期、SHA256和同目录原文。每次读取验证字节，解析缓存按内容身份受限；损坏、跨账户或范围不匹配必须保留未确认状态，不能静默覆盖。

Compose模板仅转发上述可选项，默认空值、不启用；现有数据挂载可承载独立证据目录，不添加卷或改Token/生产查询。未来启用顺序是先核准兼容API和web版本，再显式发布证据并配置入口，不能让旧前端重算覆盖新后端。调度器不在本轮修改；下载/定时发布尚未接入生产，不声明已经自动日终确认。

生产启用、定时发布安排与历史写账仍须另行核准；添加代码不代表已激活日结数据源。现有生产查询和Token不变，GET读取没有网络刷新和写入副作用。

官方样本日结从旧35067.987508493 USD纠正为34909.877129397 USD，期间盈亏从-4575.947491507纠正为-4734.057870603 USD。差额-158.110379096恰为净应计，现金和证券估值不变。

上述是私有固定输入隔离回放预期，不是当前生产观察。原币明细、历史完整集合、费用及全局收支对账分别验收，不能以日结解析相等代替全账可信。

## 2. 完整持仓集合与历史删除预检

`ibkr_snapshot_alignment`从完整账户/业务日XML生成稳定身份集合，双表同时比较额外、缺失、匹配项。默认dry-run只读；完整来源、数值精度、源字节、前态与审批均须匹配。未知来源和独立手工行不能按账户或名称推断归属。

历史模式为`historical_delete_only`：仅删除有证明且获精确计划审批的额外行，所有匹配行逐字节保留，不插入缺失项、不重写价格/成本/数量。正常`source_sync`是另一个受信任完整来源入口，不能把HTTP参数或报表本身当审批；本轮未接生产collector，不声称已替换旧UPSERT写入路径。

真实样本的隔离演练两表各16→15，30条保留行逐字节一致；失败回滚、成功应用及重试零变更通过。原完整替换曾提出另12条快照更新，现旧14操作计划失效，只有两删除候选。其他32个数值差异来源尚未查清，保持不改写，不升级为完整历史验收。

复制演练保留原字段类型/主键/旧唯一约束，但不声称所有外键和生产环境均已重现。生产应用、回滚和数据恢复仍需分别核准，代码存在不等于执行许可。
