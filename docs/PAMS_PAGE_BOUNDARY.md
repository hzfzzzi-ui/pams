# PAMS 页面与接口边界

本文定义当前页面与 API 的职责，实际能力开关及运行版本按配置与对应发布记录核对。

| 页面 | 职责 | 主要模块／接口来源 |
| --- | --- | --- |
| investments.html | 默认首页；持仓、交易、分析、风险、目标配置 | holdings、holdings_categories、transactions、lookthrough、portfolio_risk、portfolio_config；由对应 API 服务给出业务结果 |
| ledger.html | 收支、资金流转、待确认与异常摘要 | ledger_cashflow；cashflow fact 与 ledger 服务 |
| more.html | 低频功能入口 | more；账户、数据源及导入子入口 |
| accounts.html | 账户核准、余额、银行账单与划转匹配 | bank_reconcile；accounts、bank-reconcile 服务 |
| data_sources.html | 同步状态、覆盖与数据质量 | data_sources；sync center |
| account_import.html | 导入暂存、核对、预检和显式发布入口 | account_import；访问、schema、预检和发布开关分别生效 |

页面存在不代表权限已开启、事实可写或业务已验收。开发阶段见 [GitHub PR](https://github.com/hzfzzzi-ui/pams/pulls)，实际能力核对对应发布记录/配置，导入细节见 [契约](IMPORT_AND_FACTS.md)。

## 导航和兼容

- 底部主导航为投资、收支、更多，风险主入口在投资页内。
- index.html 重定向 investments.html；risk.html 重定向投资风险子页。
- 旧 holdings、transactions、cashflow、backtest、strategy、watchlist 独立 HTML 入口在构建 nginx 配置中返回 404；研究页面及相关 JS 已移除。
- nginx 配置由 frontend/Dockerfile 生成，是构建配置的唯一来源。
- 生成的手机样式与基础样式的选择见 [前端设计规则](PAMS_FRONTEND_DESIGN_SYSTEM.md)。

## 主要 API


| API | 功能 |
| --- | --- |
| `GET /summary2/latest` | 投资总览，顶层组合价值使用已发布估值状态 |
| `GET /api/portfolio/valuation-state` | 查询当前已发布估值状态 |
| `POST /api/portfolio/valuation-state/publish` | 发布或重算组合估值状态 |
| `GET /holdings/latest` | 查询最新持仓快照 |
| `GET /holdings/by-category/{category}` | 按分类查询持仓 |
| `GET /investment/return-series` | 查询组合收益曲线 |
| `GET /investment/section-return-series` | 查询资产桶收益曲线 |
| `GET /nav/weekly?latest=true` | 查询 NAV 序列，并让终点对齐最新估值状态 |
| `GET /api/portfolio/risk-disclosure` | 查询风险披露页数据 |
| `GET /api/portfolio/config` | 查询配置页目标规则和偏离情况 |
| `GET /api/investment-transactions` | 查询投资交易事实列表 |
| `GET /api/accounts` | 查询账户视图 |
| `GET /api/ledger/workbench` | 查询流水工作台数据 |
| `POST /api/prices/*` | 刷新行情、基金净值或价格数据 |

接口前缀、查询参数和响应以当前路由及对应业务契约为准。

## 展示责任

- 前端展示及交互消费统一业务结果，不能新增临时分类或补差金额。
- 持仓、账户净值、区间收益、NAV 与归因分别按 [数据契约](DATA_AND_RETURNS.md) 追溯。
- 修改页面前核对调用方、模板和关键状态，并按 [工作流程](DEVELOPMENT_WORKFLOW.md) 选择验证范围。

## 统一外壳与内容页

`app.html` 持有唯一的“投资、收支、更多”主导航和居中内容视口，上限 430px，小屏铺满。默认展示投资；六个业务 HTML 是内容文档，移除各自的主导航。为保留既有控制器、DOM ID、导入编辑及 API 行为，第一阶段在同源 iframe 内加载内容文档，不将不同业务脚本合并到同一个全局 document。此实现不是已完成的业务模块组件化。

Nginx 将直接访问业务 HTML 的旧路径转入外壳，保留查询参数和片段；外壳内部通过 `content=1` 加载内容页。该参数仅区分页面呈现，不是授权/权限开关。`app_shell.js` 负责主导航、历史和同源页面跳转，不读取或计算金融数据；旧式程序跳转进入内层外壳时通过校验来源窗口及 origin 的消息回到外层。

投资的持仓/分析/交易/风险/配置与收支的总览/流水/账户属于相同的二级导航层，放在内容首部。收支旧页头的“流水”、副标题、口径说明和“资金流转匹配”快捷链接已移除；账户页的转账匹配功能保留。更多页移除顶部重复标题，保留主导航标签和全部资产工具入口。

内容切换仍加载对应页面，只有外层导航实例常驻，不承诺切换后保留所有页面局部筛选或滚动状态。导入的原生离页保护继续由内容页处理；真实移动设备、输入法与浏览器原生离页对话框须在上线前另行验收。技术检查不替代用户验收，未授权不合并部署。

## 前端目标架构与渐进迁移

视觉规范、功能保留和批次验收见 [前端设计与重构方案](PAMS_FRONTEND_DESIGN_SYSTEM.md)。以下是目标职责，不代表已创建目录、替换 iframe 或更换框架；方案本身不改变运行/API/数据库。

### 目标依赖

```text
应用入口 / 路由
  -> 业务模块（投资、收支、更多、账户、数据源、导入）
       -> 页面状态、展示适配、共享组件
       -> 领域 API 客户端 -> 公共 HTTP 传输
共享组件 -> 展示工具、设计变量
```

业务模块不直接调用其他模块的 DOM 或内部状态；共享组件不反向依赖业务页，不自行请求金融数据。展示适配允许字段映射、格式化、排序和筛选，不生成分类、收益、NAV、FX、风险或跨账户合并口径。

| 目标职责 | 当前入口/债务 | 迁移要求 |
| --- | --- | --- |
| 外壳与路由 | `app.html`、`app_shell.js`、`app/routes.js` | 外壳唯一持有主导航、地址及主页面切换；兼容现有六页路径、query/hash；`ui.js` 不创建导航 |
| 投资模块 | `holdings.js`、大型 `holdings_categories.js`、`lookthrough.js` 等 | 按摘要/列表/详情/图表分渲染职责，请求与事件独立；保留持仓、分析、交易、风险、配置入口 |
| 交易/收支 | `transactions.js`、`ledger_cashflow.js` 中请求、模板、事件混合 | 筛选/展开状态归所属模块，编辑和写请求与查询分开；默认十单及折叠入口保留 |
| 账户/导入/数据源 | `bank_reconcile.js`、`account_import.js`、`data_sources.js`/`sync_center.js` | 保留专用的工作流、冲突和能力判断；不为复用而合并不同写入协议 |
| 共享组件 | `ui.js`、各页模板和重复样式 | 提取底部浮层、列表、按钮、状态、图表框；通过参数/事件传递数据，不扫描其他页的 document |
| 展示工具 | `utils.js` 及各模块重复格式化 | 统一空值/零、金额精度、日期、枚举映射；历史计算明确隔离，不直接复制到新工具库 |
| HTTP 与领域请求 | `api.js` 的缓存/并发/超时，导入专用请求 | 公共层负责传输；领域层决定缓存、失效和敏感性。导入原件/预检不缓存，409 不自动重试写入 |

目录可以逐步采用 `assets/js/app/`、`features/<业务域>/`、`components/`、`data/`、`shared/`。先抽取有调用边界的模块，再迁路径；旧入口可短期转调，更新全部直接/间接 import 和缓存版本后才删除。不能仅移动大型文件并声称职责已拆分。

### 生命周期与状态

每个可挂载业务模块提供明确的初始化、清理和离页检查能力；候选接口为 `mount(root, context)` 返回清理函数，具体名称由实施选择。DOM 查询限制在模块根节点；清理事件、计时器、观察器及 Chart 实例，中止过期查询，防止晚返回响应覆盖新页面。

共享 UI 入口保留 `ui.js` 的旧调用名称，具体职责交给 `app/page_bootstrap.js`、`components/bottom_sheet.js` 与 `components/data_state.js`。预加载读取页面实际资源版本，沿用四组既有轻量读取；销毁时清理本模块计时器、空闲回调及预加载节点，等待首屏后的迟到回调不再启动新工作。已经发出的缓存读取不因这一层销毁而取消，投资业务控制器的监听与图表不在此层代管。

底部浮层负责焦点进入/返回、Tab 边界、Esc、背景 inert 及滚动锁；关闭时移除浮层 DOM 和监听，重开创建干净实例。状态组件保持既有空/错/加载语义，不请求或推导金融结果。`replaceContentAddress` 只替换同页地址并通知外壳；外壳只接收已加载内容文档的替换通知，初始化规范化交由首次 load 记录，避免覆盖来源页历史。导入自己的 push/pop、修订与离页协议继续保留。

更多、数据源及同步中心以 `features/<业务域>/controller.js` 持有根节点、请求生命周期和事件；纯模板在对应 `view.js`。旧入口导出兼容方法，每个根节点只挂载一个实例；反复 reload 不叠加同步监听，dispose 后的读取/写入结果不再更新旧页面或启动后续读取。已经提交的同步命令不被取消或自动重试。`pagehide` 清理，浏览器恢复已缓存文档的 `pageshow.persisted` 显式重挂载；不依赖脚本再次执行，也不重放写操作。

外壳 URL 的 `view` 表示页面文件名，业务内容的同名参数转存为 `content_view`，加载时还原。例如数据源“待处理”保留 `view=issues`；直接旧链接、刷新和后退保持该模式。此转义只解决导航参数重名，不更改 API 查询或权限。

投资风险/配置面板由 `features/portfolio/` 下各自的 controller 与 view、共享的只读 requests/read_session 组成。每个根节点拥有展开状态；等待投资首屏结束后才读取，退出或后续 reload 会使旧响应失效。清理解除监听并发出调用方取消信号；网络能否中止取决于注入客户端，不能把 generation 校验当作已取消网络。缓存文档恢复时重新挂载并恢复展开快照，配置详情仅由拥有它的控制器关闭。视图保留历史统计和格式化语义，不建立新的风险阈值、分类或再平衡规则。

投资主收益/NAV 两图由 `features/investment/charts/` 中 requests、state、renderer、controller 管理；历史窗口重基、事件与贡献等函数原样隔离在 `legacy_model.js`，不得据此扩展前端金融口径。入口保留 NAV 提前加载、持仓等待及分析页延迟加载顺序，兼容原图表引用。永久退出或替换控制器时销毁两图、解除窗口/序列/热点及 resize 监听；缓存文档暂存时保留当前实例，恢复无需重新执行入口。分类详情图、资产分布及剩余投资页控制器仍有自己的生命周期，不能把这两图的抽取称为整页已可统一卸载。

账户页以 `features/accounts/` 的 controller/view/actions 分离生命周期、原展示和显式命令。配置、总览、匹配、未匹配流水、导入记录继续按原依赖顺序读取；账户核准/暂缓与匹配仅响应明确点击，同一操作进行中不重复提交。根节点持有筛选、分组和展开状态，迟到响应不回写旧页面；销毁不取消已接受写入，也不再触发后续读取。缓存文档恢复只重启读取并恢复普通 UI 状态。原展示中的分组、现金与异常判断保持兼容，迁移到后端结果另列契约，不在此轮重算。

收支页以 `features/ledger/` 分离页面生命周期、请求、历史展示模型、模板、总览图表、流水/账户列表和编辑器。同一根节点重复挂载复用原实例，重复恢复事件不重复加载；退出时销毁图表、页面及浮层监听，迟到读取和已退出编辑器的返回不回写。缓存文档恢复只恢复普通筛选、分组和排序，再读取现有工作台/账户接口。编辑保持原五字段提交，同一表单进行中不重复提交，失败后允许明确重试；成功写入不会因离页被撤销，也不自动重放。历史金额/分类展示转换原样隔离，未新增业务算法。

分析与穿透使用 `features/analysis/`，由请求、状态、历史模型、SVG/热图、模板、视图和控制器分别负责。收益归因仍等待现有 NAV 启动顺序，交易归因沿用所属模块事件；风险穿透、七个暴露维度、五个归因维度与下钻保持原绑定。每个根节点只持有一组监听和 observer，退出清理图形/浮层，迟到成功或失败不覆盖新实例；缓存文档恢复保留普通维度/排序选择并重新读取。旧 FX/行业/主题等展示兼容代码原样隔离，需移交后端时另列契约，不能在图表层建立新口径。

交易页使用 `features/transactions/`，由状态、根节点/浮层作用域、历史复盘展示、列表、归因视图、编辑器、显式命令和控制器分工。默认十单、展开、折叠筛选与手动录入入口及中文方向保持；复盘保存仍为原十九字段，不改变业务规则。重复挂载复用实例，同一表单提交中去重，旧交易的迟到归因不覆盖当前表单；退出清理窗口/DOM监听、计时器及浮层，旧保存完成不关闭新表单或继续读链。缓存文档恢复只恢复普通筛选/展开及未应用筛选输入，不重放提交。共享 `shared/dom_view.js` 仅提供明确根节点内的查询、文本和错误显示，不包含业务请求或算法。

资料导入使用 `features/account_import/` 的契约、专用无缓存客户端、请求作用域、记录/映射编辑器和控制器。保留原小数字符串、权限、revision、409、手动/OCR/文件导入及明确发布；原生离页取消保留当前输入。退出中止本页读取，已接受写入继续由服务器处理；缓存文档恢复通过内存中的结果句柄保持只读保护，提前读到旧草稿不能再次放行发布。迟到写响应只登记结果，不渲染或继续写链。显式刷新核对回执/批次版本/终态后才解除保护；网络结果不明且缺少充分证据时继续只读。未完成的多文件队列不自动续传，未上传文件需重新选择；编辑内容只在本页内存中保留，不新增敏感 web storage。

| 状态 | 目标归属 | 恢复/清理规则 |
| --- | --- | --- |
| 主入口、二级页签、可分享筛选 | 路由/query/hash | 深链、刷新、前进后退一致；敏感内容不进入 URL |
| 滚动、折叠、普通筛选 | 当前会话内模块状态 | 返回同页可恢复；账户/查询条件变化时按契约失效，避免混用不同账户数据 |
| 编辑草稿与导入修订 | 所属编辑器/后端批次 | 保留现有保存方式；离页先检查，不自动发布、不新增敏感 localStorage 持久化 |
| API 数据 | 领域请求层 | 缓存 key 包含真实请求范围；写入成功仅失效相关读取；部分失败保留已知状态并标注 |

替换 iframe 前必须满足：六页均可安全初始化/退出；统一离页检查且取消时 URL/选中态不变；旧路径、hash、刷新/后退不丢状态；导入权限/revision/409 处理保持；无重复主导航、嵌套滚动或遗留监听；真实手机键盘、安全区、原生离页流程验收完成。迁移可逐页进行，但同一路由任一时刻只能由一个容器拥有，不能同时启动 iframe 和模块控制器。

### 与后端并行重构的接口清单

前端继续以现有 API 或明确标注的固定测试数据为准。后端“主表、来源表、辅助表”如何组织不成为浏览器取表逻辑。以下仅为需要协作的语义，不是新增 API 的已定字段或已实施契约；实施前先复用后端已有等价字段。

| 消费场景 | 需要后端明确的结果 | 当前核查点 |
| --- | --- | --- |
| 持仓盈亏/收益率 | 已实现、未实现、累计盈亏分别的口径；收益率分母、是否有定义及币种 | `holdings.js` 的浮盈/已实现回退，`utils.js` 的成本回推和收益率 |
| 合并持仓 | 稳定分组身份、成员、各字段汇总含义、价格/成本/状态及完整性 | `aggregateMobileHoldingRows`；不能由同名证券推断同一资产 |
| 账户摘要 | gross/归属后资产、现金、负债和净值的范围、日期、FX/来源/质量 | `holdings_categories.js` 的账户投影与回退依赖 |
| 曲线和归因 | 时间窗口、NAV 与收益区分、事件及基数、已确认/预估、缺口 | 图表只绘制返回值，不补齐缺失收益或临时平滑金融序列 |
| 分类/风险/配置 | 分类维度、风险级别与依据、目标/实际/偏离及计算时点 | 服务端统一结果，前端不建立名称分类或风险阈值规则 |
| 导入写入结果恢复 | 稳定操作身份、处理状态、目标批次、最终修订和明确失败证据 | 无 revision 的创建/上传/解析丢失回执时，现有草稿读取不足以证明操作结果；本轮保持只读，不自动重试 |

导入结果恢复的待协作提案（未实现、未修改现有接口）：写请求接受 `client_operation_id: string` 作为稳定幂等身份，回执返回 `operation_id: string`；候选只读查询 `GET /api/account-import/operations/{operation_id}`，未获回执时可按 `client_operation_id` 查询。响应需明确 `operation_kind: create|upload|parse|save|preview|publish`、`status: processing|succeeded|rejected|unknown`、`batch_id: string|null`、`revision_before/revision_after: integer|null`、`accepted_at/completed_at: timestamp|null`、`error_code: string|null`，并约定与原写入的事务/幂等关系、权限和保存期。`unknown` 或查无记录不能自动等同未执行；这些字段由后端确认后再绑定，浏览器不根据名称或时间猜测写入是否完成。当前保护仅覆盖同文档恢复内存，不宣称跨全刷新/多设备的服务端幂等。

每项接口提案必须列出 endpoint、请求参数、现有/新增 JSON 字段名及类型、资产/账户身份、业务日期/生成时间、币种与 FX 日期、归属与 gross 范围、精度、枚举、null/真实零、来源/质量和正常/缺失/多账户示例。未经后端契约确认不在前端新增公式，也不宣称历史计算已消除；旧行为与新契约有差异时单列影响，再迁移绑定和删除旧实现，禁止长期双算择优。

### 证据与回归边界

样式和结构迁移使用固定 API 响应，明确 fixture 范围及数据指纹；核对字段文本、入口、金额、币种、日期、枚举和 null 展示，视觉变化之外的业务差异必须解释。接口契约测试验证响应语义，组件交互测试验证真实操作，跨页浏览器测试验证导航/状态/错误恢复；不只靠字符串或样式快照证明行为。CI 和发布要求沿用 [开发工作流程](DEVELOPMENT_WORKFLOW.md)，本方案不修改 workflow。
